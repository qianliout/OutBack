# Kafka 数据可见性与隔离级别笔记

## 1. 核心结论

Kafka 仅支持两种隔离级别，通过消费者配置 `isolation.level` 控制，核心差异在于**是否可见未提交的事务消息**。

| 隔离级别  | 配置值 (`isolation.level`) | 可见性边界 | 特性 | 适用场景 |
| --- | --- | ---| --- | --- | 
| **读未提交** | `read_uncommitted` (默认) | **HW** (High Watermark)      | 允许**脏读**。只要消息同步到 ISR 即可见，无论事务是否提交。       | 日志收集、实时指标（容忍少量脏数据，追求低延迟）。      |   
| **读已提交** | `read_committed`        | **LSO** (Last Stable Offset) | 拒绝脏读。仅可见已 Commit 的事务消息；Abort 的消息自动过滤不可见。 | 金融交易、库存扣减（要求 Exactly-Once 语义）。 |    

## 2. 关键机制原理

### 2.1 两个核心水位线

- **HW (High Watermark)**：
    - 定义：ISR 中最小的 LEO。
    - 作用：保证**数据不丢失**（副本同步安全线）。
    - 局限：无法区分消息是否属于未完成的事务。
- **LSO (Last Stable Offset)**：
    - 定义：`min(HW, 所有活跃事务的起始 Offset)`。
    - 作用：保证**事务原子性**。
    - 逻辑：若有事务进行中，LSO 卡在事务开始处，阻塞后续消息可见性，直到事务 Commit/Abort。

### 2.2 实现流程

1. **事务写入**：Producer 发送消息，Broker 记录为“未提交”状态，HW 推进但 LSO 停滞。
2. **控制消息 (Control Batch)**：事务结束时，Broker 追加特殊的 `COMMIT` 或 `ABORT` 控制记录。
3. **消费过滤**：
    - `read_committed` 消费者拉取时，解析控制消息。
    - 遇 `ABORT`：直接丢弃该事务所有数据（应用层无感知）。
    - 遇 `COMMIT`：LSO 跃迁，放行数据。

## 3. 生产环境最佳实践

- **默认陷阱**：开启 Producer 事务后，**必须**显式将 Consumer 配置为 `read_committed`，否则事务失效，下游仍会处理脏数据。
- **性能权衡**：`read_committed` 会引入轻微延迟（需等待事务提交）和 CPU 开销（计算 LSO、过滤控制消息）。
- **队头阻塞**：若存在长事务，LSO 会被卡住，导致该 Partition 上后续已提交的小事务也无法被 `read_committed` 消费者读取。

## 4. 代码示例 (Java)

```java
// 强一致性场景必备配置
props.put("isolation.level", "read_committed"); 
// 配合 Producer 端：enable.idempotence=true + 事务 API
```
