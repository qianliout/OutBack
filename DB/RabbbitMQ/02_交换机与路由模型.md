# 02_交换机与路由模型

## 常用交换机与路由场景

### Direct Exchange 定向路由
Direct 交换机要求消息的 Routing Key 与队列绑定的 Binding Key 完全匹配。
适用场景：一对一的精准消息分发，例如系统日志按级别路由到不同的处理队列。

### Fanout Exchange 广播模式
Fanout 交换机忽略 Routing Key，将消息路由到所有与之绑定的队列。
适用场景：一对多的广播通知，例如全局配置更新下发给所有服务节点。

### Topic Exchange 主题订阅
Topic 交换机允许使用通配符进行模糊匹配。符号 * 匹配一个单词，符号 # 匹配零个或多个单词。
适用场景：复杂的按主题分发，例如订单系统的消息可以根据业务线和地域进行多维度路由。

### Headers Exchange 头部匹配
Headers 交换机不依赖 Routing Key，而是匹配消息头部的键值对属性。
适用场景：需要根据复杂的业务属性进行过滤，性能较差，生产环境中极少使用。

### 对比 Kafka 单一基于 Topic 的分发模式
RabbitMQ 的路由计算发生在服务端，通过上述四种交换机可以实现非常灵活的分发拓扑图。
Kafka 只有 Topic 概念。如果需要类似 RabbitMQ 的分发，通常需要业务系统消费 Topic 后自行进行过滤计算，或者使用 Kafka Streams 进行流处理转化，路由灵活性远不如 RabbitMQ。
