# 05_生产环境实战

## 生产环境常见问题解决

### 如何保证消息不丢失
RabbitMQ 保证不丢失需要三点配置：生产者开启确认机制，服务端配置交换机与队列和消息全面持久化，消费者开启手动确认并确保业务处理完毕再调用确认接口。
Kafka 保证不丢失需要：生产者设置所有副本落盘机制，配置合适的重试次数，消费者关闭自动提交，改为手动提交偏移量。

### 如何避免消息重复消费
由于网络抖动，RabbitMQ 和 Kafka 都可能发生重试导致重复投递，无法在中间件层面做到绝对的精准一次。
必须在业务消费端实现幂等性。常见的方案包括：利用数据库的唯一索引去重、利用 Redis 记录已处理的消息标识进行拦截、或者基于业务状态机的防重校验。

### 如何保证消息顺序性
RabbitMQ 保证顺序性非常困难。必须保证只有一个生产者、队列只能有一个消费者。如果消费者崩溃导致消息重新入队，顺序就会被打乱。
Kafka 原生保证分区级别的顺序性。只要确保同一类消息通过相同的特征值路由到同一个分区，并且由单线程消费该分区，就能严格保证顺序。

### 延迟队列的实现方案
RabbitMQ 可以通过结合消息过期属性和死信队列来实现延迟处理。现在业界更推荐安装官方的延迟消息交换机插件来实现。
Kafka 没有原生的延迟队列功能。通常的做法是按不同的延迟级别创建不同的 Topic，通过独立的服务定时拉取数据，或者借助时间轮算法在业务内存中做延迟调度。
