# 第五部分：M1 Mac 上的 Docker 环境搭建（学习用途）

本部分将为你提供在 **Apple Silicon M1 Mac** 上使用 Docker 部署主流向量数据库的完整实践指南。我们将对比 **Milvus** 和 **Qdrant** 两个生产级开源系统，最终推荐最适合 M1 环境学习的方案，并提供可运行的 `docker-compose.yml` 配置、健康检查命令及常见问题解决方案。

---

## 1. 推荐使用哪个数据库？为什么？

### 候选数据库对比（Milvus vs Qdrant）

| 维度 | Milvus | Qdrant |
|------|--------|--------|
| **ARM64 支持** | ✅ 官方提供 ARM64 镜像（`milvusdb/milvus:v2.4.3`) | ✅ 官方支持 ARM64（Rust 编译友好） |
| **架构复杂度** | ⚠️ 分布式微服务，组件多（etcd, minio, pulsar/kafka） | ✅ 单进程，支持集群模式，更轻量 |
| **学习曲线** | 高（需理解多个组件协同） | 中（API 简洁，文档清晰） |
| **底层原理清晰度** | ✅ 极高（存算分离、Segment 模型、WAL） | ✅ 高（RocksDB 存储、HNSW 实现透明） |
| **Golang 客户端支持** | ✅ 官方提供 `milvus-sdk-go/v2` | ✅ 社区维护良好（`qdrant/go-client`） |
| **M1 兼容性** | ✅ v2.3+ 支持 ARM64 | ✅ 原生支持 |
| **资源消耗** | 高（需 8GB+ 内存） | 低（2-4GB 可运行） |

### ✅ 最终推荐：**Qdrant**

**理由**：
- 更适合 **M1 Mac 学习环境**：单容器部署，启动快，资源占用低
- 架构简洁但功能完整，便于理解核心机制
- API 设计现代，Golang 客户端易用
- 源码（Rust）质量高，适合后续深入阅读
- 同时支持单机与集群，平滑过渡到生产

> 💡 **备注**：Milvus 更适合在 Kubernetes 上学习分布式架构，Qdrant 更适合本地快速掌握向量数据库本质。

## 2. Qdrant Docker Compose 配置（M1 ARM64 友好）

### `docker-compose.yml`

```yaml
# docker-compose.yml
version: '3.7'

services:
  qdrant:
    # 使用官方 ARM64 支持镜像
    image: qdrant/qdrant:v1.10.0
    container_name: qdrant-local
    ports:
      - "6333:6333"   # HTTP API
      - "6334:6334"   # gRPC (可选)
    environment:
      - QDRANT__SERVICE__HTTP_PORT=6333
      - QDRANT__SERVICE__GRPC_PORT=6334
      # 启用 Dashboard (v1.7+)
      - QDRANT__ENABLE_SERVICE_WEB_UI=true
      # 数据持久化目录
      - QDRANT__STORAGE__SNAPSHOTS__DIRECTORY=/qdrant/snapshots
      - QDRANT__STORAGE__DATASETS__DIRECTORY=/qdrant/datasets
    volumes:
      - ./qdrant_data:/qdrant/storage  # 持久化数据
    # 推荐：为 M1 分配足够内存
    deploy:
      resources:
        limits:
          memory: 4G
        reservations:
          memory: 2G
    # 健康检查
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:6333/readyz"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 10s
```

> ✅ **说明**：
> - 使用 `qdrant/qdrant:v1.10.0`，官方支持 ARM64
> - 持久化目录映射到本地 `./qdrant_data`
> - 健康检查确保服务完全启动

---

### 启动命令

```bash
# 创建目录
mkdir -p qdrant_data

# 启动服务
docker-compose up -d

# 查看日志
docker-compose logs -f qdrant
```

预期输出：
```
qdrant-local | 2025-03-20T08:00:00Z  INFO qdrant: Qdrant is ready to serve requests
```

## 3. 如何验证服务健康？

### (1) HTTP 健康检查

```bash
# 检查就绪状态
curl http://localhost:6333/readyz
# 返回: ok

# 检查存活状态
curl http://localhost:6333/health
# 返回: {"status":"ok"}

# 获取版本信息
curl http://localhost:6333/version
# 返回: {"version": "1.10.0"}
```

### (2) Web UI（Dashboard）

Qdrant 提供内置 Web UI（v1.7+）：

- 访问：[http://localhost:6333/dashboard](http://localhost:6333/dashboard)
- 功能：查看集合、监控查询、执行搜索

## 4. 常见 M1 兼容性问题及解决方案

### ❌ 问题 1：镜像架构不匹配（`no matching manifest for linux/arm64`）

**原因**：拉取了 x86_64 镜像，不支持 ARM64。

**解决方案**：
- 使用官方明确支持 ARM64 的镜像（如 `qdrant/qdrant`, `milvusdb/milvus`）
- 避免使用 `latest` 标签，指定具体版本
- 检查镜像支持架构：

```bash
docker inspect qdrant/qdrant:v1.10.0 | grep Architecture
# 输出: "Architecture": "arm64"
```

---

### ❌ 问题 2：内存不足导致 OOM 或启动失败

**原因**：Docker Desktop 默认内存为 2GB，HNSW 索引构建需大量内存。

**解决方案**：
- 在 Docker Desktop 设置中将内存提升至 **6-8GB**
- 或在 `docker-compose.yml` 中限制 Qdrant 内存使用（如上配置）

---

### ❌ 问题 3：权限问题（`Permission denied` on volume mount）

**原因**：M1 上 Docker 文件系统权限与 macOS 不一致。

**解决方案**：
- 确保 `./qdrant_data` 目录可写：

```bash
chmod 777 qdrant_data  # 仅学习环境使用
```

- 或使用命名卷（Named Volume）：

```yaml
volumes:
  qdrant_storage:
    driver: local

services:
  qdrant:
    volumes:
      - qdrant_storage:/qdrant/storage
```

---

### ❌ 问题 4：端口冲突（`port is already allocated`）

**原因**：6333 端口被占用。

**解决方案**：
- 更改映射端口：

```yaml
ports:
  - "6335:6333"
```

- 查找并杀死占用进程：

```bash
lsof -i :6333
kill -9 <PID>
```

---

### ❌ 问题 5：gRPC 连接失败（IPv6 问题）

**原因**：某些 Go 客户端默认尝试 IPv6。

**解决方案**：
- 绑定到 IPv4：

```yaml
environment:
  - QDRANT__SERVICE__HOST=0.0.0.0
```

- 客户端连接时使用 `http://127.0.0.1:6333`
