### **1. 学习目标**

- 掌握向量数据的基本概念（嵌入、距离度量、高维空间特性）
- 理解向量数据库的核心组件及其作用（存储引擎、索引结构、查询处理器、元数据管理、分布式协调）
- 能在 M1 Mac 上使用 Docker 部署主流开源向量数据库
- 使用 **Golang** 实现完整的向量数据 CRUD 操作（含元数据过滤、批量插入、近似最近邻搜索）
- **深入理解底层机制**：包括但不限于：
  - 向量索引的构建、更新、合并与持久化过程
  - 存储引擎设计（内存 vs 磁盘、WAL、LSM-tree 或类似结构的应用）
  - 向量索引的动态更新策略（如 HNSW 的增量插入、IVF 的聚类更新）
  - 并发控制与事务模型（是否支持 ACID？如何处理写冲突？）
  - 查询执行流程与优化器设计（过滤下推、预筛选、多条件组合查询）
  - 内存管理与缓存机制（向量缓存、索引缓存、LRU 策略等）
  - 容错与恢复机制（崩溃恢复、副本同步、一致性协议）
  - 性能瓶颈分析与调优方法（CPU、内存、IO、网络）

### **2. 环境与技术栈要求**

- **开发/学习环境**：macOS（Apple Silicon M1）
- **容器平台**：Docker（推荐 Docker Desktop 或 Colima），需支持 ARM64 镜像
- **编程语言**：Golang（最新稳定版），要求使用官方或成熟社区客户端库
- **数据库选型要求**：
  - 优先考虑 **生产级、开源、支持 ARM64 的向量数据库**（如 Milvus, Qdrant, Weaviate）
  - **排除仅适合轻量级或嵌入式场景的系统**（如 Chroma）
  - 对比分析 2-3 个候选数据库在以下维度的表现：
    - 架构设计（单机 vs 分布式）
    - 存储与索引分离设计
    - 支持的索引类型（HNSW、IVF、PQ 等）及更新能力
    - 是否支持实时写入与增量索引构建
    - 生产环境中常见部署模式（Kubernetes、裸金属）
    - 社区活跃度与文档完整性
  - **最终选定一个最适合深入学习底层原理的数据库作为主线工具**

### **3. 学习提纲要求**

请按以下结构组织内容，确保每一部分都包含**原理讲解 + 实践示例 + 底层机制剖析**：

#### **第一部分：向量数据基础**

- 向量嵌入的本质：从文本/图像到高维空间
- 常见 embedding 模型简介（BERT、CLIP、OpenAI、本地开源替代）
- 距离度量的数学基础：余弦相似度、L2、内积的等价性与归一化
- 高维空间的“诅咒”与近似搜索的必要性

#### **第二部分：向量数据库系统架构全景**

- 与传统数据库的根本差异（向量不是标量）
- 典型架构层次图（接入层、查询层、索引层、存储层、元数据层）
- 分布式架构设计模式（如 Milvus 的微服务拆分：coordinator、worker、storage）
- 存算分离理念及其优势

#### **第三部分：核心索引算法的底层实现**

- **HNSW**：图结构构建过程、入口点选择、动态插入策略、内存占用分析
- **IVF**：聚类中心训练（k-means）、量化误差、搜索时的“探查列表”机制
- **PQ / SQ**：向量压缩原理、精度损失与加速比的权衡
- 索引的**构建、更新、合并、持久化**全流程解析
- **增量更新 vs 全量重建**的成本对比

#### **第四部分：存储引擎与数据管理机制**

- 向量数据如何存储？（内存映射、列式存储、分块机制）
- 是否使用 WAL（Write-Ahead Log）？如何保证写入持久性？
- 向量与标量元数据的联合存储策略
- 数据分片（sharding）与负载均衡机制
- 垃圾回收与版本管理（如旧版本索引清理）

#### **第五部分：M1 Mac 上的 Docker 环境搭建（学习用途）**

- 推荐使用哪个数据库？为什么？（需支持 ARM64 且原理清晰）
- 提供 `docker-compose.yml` 示例（包含数据库服务、依赖组件如 etcd/minio）
- 如何验证服务健康？提供 `curl` 或 CLI 测试命令
- 常见 M1 兼容性问题及解决方案（如镜像架构、权限、内存限制）

#### **第六部分：Golang 开发实践（面向生产设计）**

- 推荐 Golang 客户端库（官方 or 社区维护良好）
- 示例代码涵盖：
  - 连接池配置
  - 创建集合（指定维度、索引类型、距离度量）
  - 插入带元数据的向量（批量 vs 单条）
  - 执行混合查询（向量相似度 + 标量过滤）
  - 更新与删除向量（注意：向量数据库通常不支持原地更新，需解释其背后原因）
  - 错误处理与重试机制
- 如何模拟 embedding 生成（本地模型 or 调用 API）

#### **第七部分：底层机制深度剖析（重点！）**

- **索引更新机制**：HNSW 如何支持增量插入？是否有延迟？是否需要后台合并？
- **内存管理**：向量和索引如何加载到内存？是否支持部分加载？缓存策略？
- **并发模型**：读写是否阻塞？多线程插入如何处理？
- **持久化机制**：向量数据和索引何时写入磁盘？是否支持快照？
- **故障恢复**：节点宕机后如何重建索引？依赖哪些组件？
- **性能瓶颈分析**：CPU-bound vs Memory-bound vs IO-bound 场景识别
- **调优建议**：参数调优（如 HNSW 的 M、ef_construction）、资源分配、监控指标

#### **第八部分：从学习到生产的过渡**

- 如何将 Docker 中的实践迁移到 Linux 服务器？
- 生产部署建议：Kubernetes Helm Chart、资源配置、网络策略
- 监控与告警：Prometheus + Grafana 集成
- 备份与恢复策略
- 安全性考虑（认证、授权、加密）

#### **第九部分：项目实战**

- 设计一个“语义文档搜索引擎”：
  - 数据准备（PDF/文本）
  - 使用本地模型（如 sentence-transformers）生成 embedding
  - 存储到向量数据库
  - 实现 Golang API 支持语义查询 + 时间范围过滤
  - 性能压测与结果分析
