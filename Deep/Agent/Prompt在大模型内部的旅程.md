# 一个 Prompt 进入大模型后，内部到底发生了什么？

当我们向大语言模型（LLM）输入一个 Prompt 时，模型内部会经历一系列复杂而精确的步骤，最终生成我们看到的回答。这个过程可以概括为以下几个核心阶段：

## 1. Tokenization (分词)

计算机无法直接理解人类的文字。第一步是 **Tokenization**，即将输入的文本（Prompt）分解成模型能够理解的最小单元，也就是 **Token**。

*   **什么是 Token？** Token 可以是一个单词、一个字符，或者是一个子词（sub-word）。例如，对于英文 "Transformer"，它可能就是一个 Token。对于中文 "变形金刚"，它可能会被分成 "变形" 和 "金刚" 两个 Token。
*   **为什么需要？** 通过将文本分解成有限的、标准化的 Token 集合（即模型的词汇表），模型可以用数字来表示这些 Token，从而进行数学运算。

```
Input: "今天天气真好"
Tokens: ["今天", "天气", "真好"]
Token IDs: [539, 1538, 2390] (示例 ID)
```

## 2. Embedding (嵌入)

得到 Token ID 后，模型需要理解每个 Token 的语义。**Embedding** 过程就是将每个离散的 Token ID 转换成一个高维、连续的向量（Vector）。

*   **什么是 Embedding Vector？** 这是一个包含数百甚至数千个浮点数的列表，它代表了 Token 在语义空间中的位置。
*   **为什么需要？**
    *   **捕捉语义关系：** 在这个高维空间中，意思相近的词（如 "国王" 和 "女王"）它们的向量也更接近。
    *   **数学运算：** 向量使得模型可以对词义进行数学运算，例如 `vector("国王") - vector("男人") + vector("女人")` 在理想情况下会约等于 `vector("女王")`。

经过 Embedding，一串 ID 列表就变成了一个由向量组成的矩阵。

## 3. Positional Encoding (位置编码)

标准的 Transformer 模型注意力机制本身不包含序列的顺序信息。但语言中，词语的顺序至关重要（"我打你" vs "你打我"）。因此，我们需要明确地将位置信息加入到输入中。

*   **如何实现？** **Positional Encoding** 会为输入序列中的每个位置生成一个独特的向量，然后将这个位置向量加到对应位置的 Token Embedding 向量上。
*   **目标：** 这样，即使是同一个 Token，在不同的位置也会有不同的最终表示，模型从而能够区分词序。

至此，我们得到了一个既包含语义信息又包含位置信息的输入矩阵，准备好进入模型的核心——Transformer。

## 4. Transformer Blocks (核心处理层)

输入矩阵会流经数十个甚至上百个相同的 **Transformer Block**。每个 Block 都包含两个关键的子层：

### a. Multi-Head Self-Attention (多头自注意力机制)

这是 Transformer 最核心的创新。它允许模型在处理一个 Token 时，动态地评估输入序列中所有其他 Token 对它的重要性（"注意力权重"）。

*   **它做什么？** 对于序列中的每个词，自注意力机制会计算它与所有其他词（包括它自己）的关联度得分。这个得分决定了在生成这个词的新表示时，应该从其他词那里汲取多少信息。
*   **"多头"是什么意思？** "多头"（Multi-Head）意味着这个过程会并行地进行多次。每个 "头" 关注输入序列的不同方面（比如有的头关注语法结构，有的头关注语义关联）。最后将所有头的结果拼接起来，从而获得一个更丰富、更全面的信息表示。

简单来说，自注意力机制让模型理解了句子内部的依赖关系，比如代词 "它" 指代的是哪个名词。

### b. Feed-Forward Network (前馈神经网络)

自注意力层的输出会经过一个简单的全连接前馈神经网络（FFN）。

*   **它做什么？** FFN 对自注意力层输出的每个位置的向量进行一次非线性变换。这可以看作是对信息的进一步加工和提炼，增加了模型的表示能力。
*   **结构：** 通常由两个线性层和一个激活函数（如 ReLU 或 GeLU）组成。

每个 Transformer Block 都会重复 "自注意力 -> FFN" 这个过程，并辅以残差连接（Residual Connections）和层归一化（Layer Normalization）来帮助模型更深、更稳定地训练。每一层 Block 都会对输入矩阵进行一次更深层次的抽象和重构。

## 5. Output Generation (生成输出)

当最后一个 Transformer Block 处理完毕后，模型就进入了生成回答的阶段。

### a. Logits (原始预测)
最后一层的输出向量会被送入一个最终的线性层，将其维度映射到整个词汇表的大小。这个输出被称为 **Logits**。每个维度的值代表了模型预测下一个 Token 是词汇表中对应词的原始、未经归一化的分数。

### b. Softmax
Logits 经过 **Softmax** 函数处理，转换成一个概率分布。现在，每个维度的值都在 0 到 1 之间，并且所有值的总和为 1。这个值代表了模型认为下一个 Token 是词汇表中某个特定词的概率。

### c. Sampling (采样/解码)
有了概率分布后，模型需要选择一个 Token 作为输出。有多种策略：
*   **Greedy Search (贪心搜索)：** 总是选择概率最高的那个 Token。这种方法简单快速，但可能导致重复和无趣的回答。
*   **Beam Search (束搜索)：** 在每一步保留 K 个最可能的序列，并在下一步从这 K 个序列出发继续生成，最后选择整体概率最高的序列。
*   **Sampling with Temperature & Top-p/Top-k：** 引入随机性。通过调整 **Temperature** 参数，可以改变概率分布的平滑度（温度越高，分布越平缓，越可能选到低概率词，回答越具创造性）。**Top-k** 和 **Top-p** 则限制了采样范围，只在最可能的前 k 个或累积概率达到 p 的词中进行采样。

这个 "生成一个 Token -> 将其加入输入 -> 再次预测下一个 Token" 的过程会不断重复，直到模型生成一个特殊的终止符（[EOS] Token）或达到最大长度限制。
