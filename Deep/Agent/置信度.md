# LLM 置信度评估方法

## 核心问题
LLM 本质是“下一个词预测器”，**原生状态下无法提供可靠、准确的置信度**。模型内部计算的 token 概率不能直接等同于答案的正确概率，且经过指令微调后模型往往过度自信。

---

## 1. 内部状态（Logits / 概率）
- **原理**：查看生成第一个或关键 token 的原始概率
- **局限**：不可靠。即使答案错误，模型也可能以 99.9% 的概率输出第一个 token


## 2. Prompt 强制输出置信度
- **方法**：设计提示词，要求模型以结构化格式输出答案 + 自评分数（0-100%）
- **改进**：结合思维链，先输出推理过程再自我评估，结果更准确
- **注意**：自评分数往往偏高，需将其视为模型的“主观感觉”

---

## 3. 多次采样（语义熵 / Self-Consistency）
- **操作**：用较高 Temperature（如 0.7-1.0）多次调用模型生成回答
- **判断**：
  - **高置信度**：多次结果语义一致
  - **低置信度**：答案矛盾或出现“不知道”“可能”等模糊表述
- **进阶**：计算语义熵，量化结果在语义空间的离散程度

---

## 4. 外部验证（RAG + 向量检索）
- **适用场景**：事实性答案的客观置信度评估
- **步骤**：
  1. 模型生成答案
  2. 将答案与问题向量化
  3. 在可信知识库中检索相关文档
  4. 计算向量相似度
- **逻辑**：相似度高 → 有权威来源支撑 → 置信度高

---

## 5. 微调置信度头（高成本场景）
- **做法**：对开源模型微调，在数据中加入置信度标签，训练分类头预测答案正确概率
- **优势**：效果最佳
- **劣势**：成本高，适用于医疗、法律等高风险领域

---

## 最佳实践建议
1. **轻量级场景**：用 Prompt 强制输出“推理 + 答案 + 自评”，快速筛选明显不确定的情况
2. **关键场景**：引入多次采样，若结果不一致则判定为低置信度
3. **事实性问题**：优先使用 RAG，置信度由检索匹配度决定，可控性更强
4. **核心原则**：不要轻信模型直接给出的置信度百分比，必须结合工程手段交叉验证
