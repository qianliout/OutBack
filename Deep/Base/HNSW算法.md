# HNSW 
## 1. 背景与动机

### 为什么需要近似最近邻（ANN）？

在机器学习和数据检索领域，我们经常需要从海量数据中找到与查询点最相似的几个点。这被称为 **K-最近邻（K-NN）** 搜索。当数据量很小（例如几千个点）时，我们可以通过**精确近邻（Exact Nearest Neighbor, ENN）**搜索来实现，即计算查询点与数据库中每个点的距离，然后排序，返回距离最小的 K 个。这个过程的复杂度是 O(N*d)，其中 N 是数据点数量，d 是数据维度。

然而，在现代 AI 应用中，N 通常是百万、十亿甚至更大规模，d 也是成百上千（例如，语言模型的词嵌入维度通常是 768 或更高）。此时，O(N*d) 的线性扫描变得不可行。

**近似最近邻（Approximate Nearest Neighbor, ANN）** 应运而生。它牺牲了一点点精度（即不保证 100% 找到真正的最近邻），以换取查询速度的巨大提升（通常是对数或次线性复杂度）。在绝大多数场景下，这种“近似”的方案足以满足业务需求，其带来的性能收益远超微小的精度损失。

### HNSW 在 ANN 领域中的地位和优势

ANN 领域有多种算法，HNSW 是一种基于图的算法，并凭借其出色的性能和泛用性，成为了目前业界的主流选择之一。

-   **对比 LSH (Locality Sensitive Hashing)**：LSH 通过一系列哈希函数将相似的点映射到同一个“桶”中。虽然有理论保证，但实践中为了达到高召回率，通常需要大量的哈希表，导致内存占用巨大，且参数难以调节。
-   **对比 Tree-based (如 KD-Tree, Annoy)**：树状结构（如 KD-Tree）在处理低维数据时非常高效。但随着维度增加（通常 d > 20），“维度灾难”现象会导致其性能急剧下降，甚至退化为线性扫描。
-   **对比 IVF (Inverted File, 如 FAISS-IVFFlat)**：IVF 系列通过 k-means 等聚类方法将数据空间划分为多个单元（cells）。查询时，只搜索查询点附近的少数几个单元。其性能高度依赖数据分布和 `nprobe`（查询时探索的单元数）参数的选择。对于分布不均的数据，效果可能不佳。

**HNSW 的核心优势**：
1.  **卓越的性能**：提供了极佳的查询速度和召回率（accuracy）的平衡，通常优于上述方法。
2.  **鲁棒性强**：对数据分布不敏感，在各种数据集上都表现稳定。
3.  **扩展性好**：能够很好地处理高维数据，有效对抗“维度灾难”。
4.  **支持动态数据**：原生支持在线插入数据，比需要定期重构索引的 IVF 等方法更灵活。

## 2. 核心思想

HNSW 的名字已经揭示了其三大核心：**Hierarchical (分层)**、**Navigable (可导航)** 和 **Small World (小世界网络)**。

### “小世界网络”是什么？如何启发 HNSW？

“小世界网络”源于社会学中的“六度分割”理论，它具备两个典型特征：
1.  **高聚集性**：网络中的节点倾向于形成紧密的团簇，即你的邻居之间也很有可能是邻居。
2.  **短路径长度**：从网络中任意一个节点到另一个节点，平均只需要经过很少的几步。

这种结构通常由两种连接共同构成：负责“聚集”的**短程连接（short-range links）**和负责“缩短路径”的**长程连接（long-range links）**。

HNSW 正是构建了这样一个图：每个数据点是一个节点，节点间的边代表它们的邻近关系。查询时，可以像在高速公路（长程连接）和本地道路（短程连接）上导航一样，从任意入口点开始，通过贪心策略（总是走向离目标更近的邻居）快速逼近查询目标。

### 分层结构（Hierarchical）与跳表（Skip List）的类比

早期的图算法（如 NSW）只在单层图上搜索，虽然有效，但长程连接和短程连接混杂，导致导航效率不高。HNSW 引入了分层结构，这是其最大的创新，思想类似于数据结构中的**跳表（Skip List）**。

-   **跳表**：在一个有序链表的基础上，构建多级索引。最底层是完整的链表，每往上一层，就抽取部分节点作为“快速通道”。查询时从顶层开始，可以“跳过”大量节点，快速定位目标区域，再逐层向下细化。

-   **HNSW 的分层图**：
    -   **Layer 0**：包含所有数据点的最底层图，节点连接最密集，负责精细导航。
    -   **Layer 1, 2, ...**：每一层都是下一层的“子集”，越往上，节点越稀疏。顶层的节点最少，但它们之间的连接是图中最长的“高速公路”。

**文字图示：HNSW 分层结构**
```
      L2:  A -------------------------------------- G  (长程连接)
           |                                        |
      L1:  A ------- C ---------------- E --------- G  (中程连接)
           |         |                   |           |
      L0:  A -- B -- C -- D -- E -- F -- G -- H -- I  (短程/精细连接)
```
查询时，从顶层 L2 的入口点开始，迅速定位到 G 附近。然后进入 L1，从 G 开始进一步找到 E。最后在 L0 从 E 开始进行最终的精细搜索，从而找到真正的最近邻。这种由粗到精的策略极大地提高了搜索效率。

### 可导航性（Navigable）的含义

可导航性指的是图中的贪心搜索策略的有效性。由于 HNSW 图同时具备小世界网络属性和清晰的层次结构，使得从任意节点出发，沿着“离查询目标最近”的邻居移动，能够稳定、快速地收敛到目标区域。

## 3. 关键参数详解

理解 HNSW 的参数是有效使用它的关键。

-   `M`：图构建过程中的核心参数，定义了**每一层**中一个节点可以拥有的最大邻居数。`M` 越大，图的连接越密集，邻居质量越高，查询精度越高，但构建时间和内存占用也随之增加。典型值在 5 到 48 之间。

-   `efConstruction`：构建索引时搜索邻居的候选集大小。在为新节点寻找 `M` 个邻居时，算法会维护一个大小为 `efConstruction` 的动态列表。该值越大，邻居选择的范围越广，最终构建的图质量越高（召回率更好），但构建速度越慢。典型值在 200 到 500。

-   `efSearch`：查询时的候选集大小。这是影响查询性能和精度的**最重要**的运行时参数。`efSearch` 越大，搜索范围越广，召回率越高，但查询延迟也越高。`efSearch` 必须大于等于 `k`（你要查找的近邻数）。

-   `M_max0`：第 0 层的最大邻居数。通常设为 `2 * M`。因为第 0 层包含了所有节点，需要更密集的连接来保证最终搜索的精度。

-   `level_mult` (或 `mL`)：一个用于计算节点层数的归一化因子，其值为 `1 / log(M)`。

### 层级分配的概率机制

新插入的节点会被分配到多少层，是随机决定的，但这个随机遵循一个指数衰减的概率分布。一个节点被分配到层 `l` 的概率为：

`P(l) = floor(-ln(uniform(0,1)) * mL)`

其中 `uniform(0,1)` 是一个 0 到 1 之间的随机数。这个公式本质上是一个**指数分布**的离散化形式。它保证了：
-   绝大多数节点只存在于底层（如 Layer 0）。
-   极少数节点能够到达非常高的层级。

这种金字塔形的结构，确保了顶层“高速公路”的稀疏性和效率。

## 4. 构建过程（Insertion）

HNSW 是动态图，节点是一个个插入的。以下是插入一个新节点 `q` 的过程：

1.  **随机生成层数 `l`**：使用上一节提到的指数分布公式为新节点 `q` 随机选择一个最高层数 `l`。

2.  **自顶向下搜索入口点**：
    -   从图的全局入口点（entry point）开始，该入口点位于图的最高层 `L_max`。
    -   在当前层（从 `L_max` 到 `l+1`），执行贪心搜索，找到离 `q` 最近的节点。
    -   将这个最近的节点作为下一层搜索的入口点。
    -   重复此过程，直到到达 `q` 的最高层 `l`。

3.  **逐层插入和连接**：
    -   从 `l` 层开始，逐层向下直到第 0 层。
    -   在每一层 `L_c`：
        a.  以上一步找到的入口点为起点，在该层执行搜索，找到 `efConstruction` 个离 `q` 最近的邻居，形成候选集 `W`。
        b.  从 `W` 中通过**启发式剪枝策略（heuristic pruning）**挑选出 `M` 个节点作为 `q` 在该层的邻居。剪枝的目的是选择空间上分布更均匀、连接质量更高的邻居，而不仅仅是距离最近的。
        c.  将 `q` 与这 `M` 个邻居建立双向连接。
        d.  为了维持图的稀疏性，检查 `q` 的新邻居们的邻居数量。如果某个邻居的连接数超过了该层的上限（`M` 或 `M_max0`），则会剪掉离它最远的连接。

### 具体数值示例（简化版）

假设 M=2, efConstruction=3, 2D 空间。
1.  **插入 P1(1,1)**: 随机层数 `l=0`。图为空，P1 成为全局入口点。
    -   `L0: {P1}`
2.  **插入 P2(5,5)**: 随机层数 `l=1`。
    -   `L1` 层为空，P2 成为 `L1` 的入口点。
    -   在 `L0`，从 P1 开始搜索 P2 的邻居。候选集只有 {P1}。连接 P2 <-> P1。
    -   `L1: {P2}`
    -   `L0: {P1 <-> P2}`
3.  **插入 P3(1,5)**: 随机层数 `l=0`。
    -   从全局入口点 P2 (`L1`) 开始搜索，P2 比 P1 更接近 P3。
    -   在 `L0`，从 P2 开始搜索 P3 的邻居。候选集为 {P1, P2}。
    -   `dist(P3, P1)=4`, `dist(P3, P2)=4`。选择 P1, P2 作为邻居。
    -   连接 P3 <-> P1, P3 <-> P2。
    -   `L1: {P2}`
    -   `L0: {P1<->P2, P1<->P3, P2<->P3}`
4.  **插入 P4(6,1)**: 随机层数 `l=0`。
    -   从 P2 (`L1`) 开始，发现 P2 比 P1 离 P4 远，导航至 P1。
    -   在 `L0`，从 P1 开始搜索。候选集 {P1, P2, P3}。`dist(P4,P1)=5, dist(P4,P2)≈4.1, dist(P4,P3)≈6.4`。
    -   选择最近的 P2 和 P1 作为邻居。连接 P4 <-> P1, P4 <-> P2。
    -   检查 P1, P2 的邻居数。P1已有{P2,P3,P4}，超过 M=2。剪掉最远的 P3。P2已有{P1,P3,P4}，剪掉最远的 P3。
    -   最终 `L0` 图结构发生相应变化。

这个过程展示了 HNSW 如何通过逐层导航和局部连接构建一个高效的图。

## 5. 查询过程（Search）

查询过程与构建过程中的搜索阶段类似，但目标是找到 `k` 个最近邻。

1.  **自顶向下寻找入口点**：与插入类似，从全局入口点开始，在每层（从顶层到 Layer 1）贪心搜索离查询点 `q` 最近的节点，并将其作为下一层的入口。

2.  **在 Layer 0 进行最终搜索**：
    -   到达 Layer 0 后，以上一步找到的入口点为起点。
    -   维护一个大小为 `efSearch` 的动态候选列表（通常是优先队列），初始时包含入口点。
    -   循环执行以下操作：
        a.  从候选列表中取出距离 `q` 最近的节点 `C`。
        b.  如果 `C` 的距离比已找到的第 `k` 个近邻还要远，则可以提前终止部分搜索路径。
        c.  遍历 `C` 的所有邻居 `N`，如果 `N` 未被访问过，则计算其与 `q` 的距离，并加入候选列表。
    -   当循环结束时，从访问过的节点中选出距离 `q` 最近的 `k` 个作为结果。

**为什么能保证高召回率？**
-   **分层导航**：确保搜索能快速进入正确的全局区域。
-   **`efSearch` 候选集**：在最终的局部区域内，`efSearch` 提供了一个足够大的“视野”，允许算法探索多个分支，弥补了纯贪心策略可能导致的“短视”问题，从而有很大概率找到真正的最近邻。

## 6. 删除操作（Deletion）

原生 HNSW 论文并未详细描述删除操作，因为它很复杂。简单地移除一个节点会破坏图的结构和连通性。

-   **软删除 (Soft Deletion)**：
    -   最简单的方式。给节点打上一个“已删除”的标记。
    -   在查询时，如果遇到已标记的节点，则直接跳过。
    -   **优点**：实现简单，速度快。
    -   **缺点**：被删除的节点依然占用内存和磁盘空间，随着删除操作增多，会造成“死节点”堆积，影响查询性能和图的质量，需要定期重建索引。

-   **硬删除 (Hard Deletion)**：
    -   物理上移除节点并修复图结构。这是一个棘手的问题。
    -   **局部修复机制**：一种可行的策略是，当节点 `D` 被删除时：
        1.  首先，将 `D` 软删除，确保进行中的查询不受影响。
        2.  在 `D` 所在的每一层，找到 `D` 的所有邻居 `N_d`。
        3.  断开 `D` 与所有邻居的连接。
        4.  关键在于**修复**。需要为 `N_d` 中的节点寻找新的邻居来“填补” `D` 留下的空缺。一个简单但昂贵的做法是，让 `N_d` 中的每个节点重新在局部区域内搜索并建立连接。
        5.  这个过程开销很大，且很难保证修复后的图质量不下降。

    -   实践中，支持硬删除的库（如 FAISS）通常会注明其性能开销较大。对于删除频繁的场景，软删除 + 定期重建索引是更常见和稳妥的方案。

## 7. 复杂度总结

-   **构建时间复杂度**：理论上约为 `O(N * log(N))`。更精确地说是 `O(N * M * log(N))`，但 `M` 通常被看作常数。
-   **查询时间复杂度**：理论上约为 `O(log(N))`。更精确地说是 `O(M * log(N))`。这是 HNSW 最大的优势——在海量数据中实现对数级别的查询。
-   **内存占用**：`O(N * M * d)`。每个节点都需要存储自身向量和指向 `M` 个邻居的指针。这是 HNSW 的主要短板，内存开销相对较大。

## 8. 实际使用指南

### 主流实现库
-   **`hnswlib`**: HNSW 算法原作者的 C++ 实现，带有 Python 接口。性能极高，是评估 HNSW 性能的基准。
-   **`FAISS`**: Facebook AI 推出的相似性搜索库，功能全面，集成了多种 ANN 算法，包括 HNSW 的 CPU 和 GPU 版本。
-   **`nmslib`**: 一个通用的非度量空间库，也包含了 HNSW 的一个高质量实现。

### Python 示例代码 (`hnswlib`)
```python
import hnswlib
import numpy as np

# --- 1. 准备数据 ---
dim = 128         # 向量维度
num_elements = 10000  # 数据量

# 生成随机数据
data = np.float32(np.random.random((num_elements, dim)))
ids = np.arange(num_elements)

# --- 2. 构建索引 ---
# 声明索引类型，'l2' 代表欧氏距离
p = hnswlib.Index(space='l2', dim=dim)

# 初始化索引
# max_elements: 最大元素数量
# ef_construction: 图构建时的邻居搜索广度
# M: 每个节点的邻居数
p.init_index(max_elements=num_elements, ef_construction=200, M=16)

# 添加数据
p.add_items(data, ids)

# --- 3. 查询 ---
# 生成一个查询向量
query_data = np.float32(np.random.random((1, dim)))
k = 5  # 查找最近的 5 个邻居

# 设置查询时的搜索广度，ef_search > k
p.set_ef(50)

# 执行 k-NN 查询
labels, distances = p.knn_query(query_data, k=k)

print(f"查询结果 (最近的 {k} 个邻居):")
print("标签:", labels[0])
print("距离:", distances[0])
```

### 如何选择参数？调参经验法则
-   **`M`**：控制内存和召回率的平衡。`M=16` 是一个很好的起点。如果内存充足且对召回率要求极高，可以尝试 32 或 48。
-   **`efConstruction`**：影响图的质量。`efConstruction=200` 是一个安全的起点。增加此值可以提升图的质量，但会显著增加索引构建时间。
-   **`efSearch`**：最重要的查询时参数。直接影响查询精度和速度。从一个较小的值开始（例如 `k + 20`），然后逐步增加，直到在你的延迟预算内达到满意的召回率。

## 9. 优化与变种

### 结合量化压缩内存
HNSW 的主要缺点是内存占用大。**向量量化（Vector Quantization）**技术可以有效解决此问题。
-   **PQ (Product Quantization)**：将高维向量切分为多个子向量，然后对每个子空间进行聚类，用聚类中心的 ID 来表示子向量。
-   **SQ (Scalar Quantization)**：将每个浮点数维度用一个整数（如 8-bit int）来表示。
-   **HNSW + PQ/SQ**：FAISS 提供了如 `IndexHNSWPQ` 的实现。在图中导航时，可以使用精确距离或从量化编码中得到的近似距离。最终存储的向量是压缩过的，极大地减少了内存占用（可达 8-32 倍压缩率）。

### 应用案例
-   **RAG (Retrieval-Augmented Generation)**：在大型语言模型应用中，HNSW 是实现“检索”模块的核心技术。它能从庞大的文档库中毫秒级地检索出与用户问题最相关的知识片段，作为上下文提供给 LLM，以生成更准确、更具时效性的回答。
-   **推荐系统**：快速找到与用户或物品 embedding 最相似的 Top-K 个物品或用户，用于生成推荐列表。
-   **以图搜图/以歌搜歌**：在图像、音频等非结构化数据的检索中，通过提取特征向量并使用 HNSW 建立索引，实现高效的内容检索。

## 10. 常见误区与注意事项

-   **向量是否需要归一化？**
    -   如果你希望使用**余弦相似度（Cosine Similarity）**进行检索，那么**必须**将所有向量归一化为单位向量（长度为 1）。
    -   一个技巧是：归一化后，使用**欧氏距离（L2）**来代替。因为对于单位向量 `A` 和 `B`，`L2_distance(A, B)^2 = 2 - 2 * cosine_similarity(A, B)`。这意味着用 L2 距离排序等价于用余弦相似度排序。这样就可以利用为 L2 优化的 HNSW 库了。

-   **高维灾难对 HNSW 的影响？**
    -   HNSW 对高维数据（几百到一千多维）表现出很强的鲁棒性，远胜于树类算法。但对于极高维度（数千维以上），距离的区分度会下降，性能仍可能受影响。此时可考虑在索引前使用 PCA 等方法进行降维。

-   **`efSearch` 过小会导致什么问题？**
    -   这是最常见的问题。如果 `efSearch` 设置得太小（例如 `efSearch = k`），查询的搜索范围会非常窄，可能会在贪心搜索过程中陷入局部最优解，导致错过真正的最近邻，从而**显著降低召回率**。务必确保 `efSearch` 有足够的余量。
