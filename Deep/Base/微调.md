## 1. 微调技术概述

### 1.1 微调的定义与分类

#### 1.1.1 基本定义

**微调(Fine-tuning)**是指在预训练模型的基础上，使用特定任务的数据进行进一步训练，以适应下游任务的技术。其核心思想是利用预训练模型学到的通用知识，通过少量的任务特定数据快速适应新任务。

**数学表达**：

$$\theta_{fine-tuned} = \theta_{pretrained} + \Delta\theta$$

其中：
- $\theta_{pretrained}$ 是预训练模型参数
- $\Delta\theta$ 是微调过程中的参数更新
- $\theta_{fine-tuned}$ 是微调后的模型参数

#### 1.1.2 微调技术分类

**按参数更新范围分类**：

| 类型 | 更新参数量 | 计算成本 | 适用场景 |
|------|-----------|----------|----------|
| **全参数微调** | 100% | 高 | 数据充足，计算资源丰富 |
| **部分微调** | 10-50% | 中 | 中等数据量，有限计算资源 |
| **参数高效微调** | <1% | 低 | 少量数据，资源受限 |

**按训练方式分类**：

1. **监督微调(SFT)**：使用标注数据进行有监督训练
2. **无监督微调**：使用无标注数据进行自监督训练
3. **强化学习微调(RLHF)**：基于人类反馈的强化学习
4. **提示学习**：通过设计提示模板引导模型输出

#### 1.1.3 微调的核心优势

**知识迁移**：
- 预训练模型已学习丰富的语言知识
- 微调过程中保留并利用这些知识
- 避免从零开始训练的高成本

**快速适应**：
- 相比从头训练，微调收敛更快
- 需要的数据量大幅减少
- 训练时间显著缩短

**性能提升**：
- 在特定任务上通常优于通用模型
- 能够学习任务特定的模式和规律
- 提供更精准的输出结果

### 1.2 微调技术发展历程

#### 1.2.1 早期阶段(2018-2020)

**特点**：
- 主要针对BERT等编码器模型
- 全参数微调为主流方法
- 关注分类、序列标注等理解任务

**代表性工作**：
- BERT微调：在GLUE基准上的成功应用
- RoBERTa：优化的预训练和微调策略
- ELECTRA：高效的预训练目标设计

#### 1.2.2 发展阶段(2020-2022)

**特点**：
- 模型规模快速增长
- 参数高效微调方法兴起
- 生成任务成为重点

**关键技术**：
- **Adapter**：在模型中插入小型网络
- **LoRA**：低秩适应技术
- **Prefix Tuning**：前缀调优方法

#### 1.2.3 成熟阶段(2022-至今)

**特点**：
- 大语言模型成为主流
- 提示学习技术成熟
- 多模态微调兴起

**前沿技术**：

## 2. 全参数微调(Full Fine-tuning)

### 2.1 显存需求计算

#### 2.1.1 显存组成要素

全参数微调的显存消耗主要来自以下部分：

$$\text{显存总量} = \text{模型参数} + \text{梯度} + \text{优化器状态} + \text{激活值} + \text{临时缓存}$$

#### 2.1.2 精确计算公式

对于包含 $N$ 个参数的模型：

**基础组件显存占用**：

| 组件 | 显存占用(字节) | 说明 |
|------|---------------|------|
| 模型参数 | $4N$ | FP32训练占4字节/参数 |
| 梯度 | $4N$ | 与参数同精度 |
| Adam优化器状态 | $8N$ | 动量+方差各占4N |
| 激活值 | $2BSL \cdot d$ | 依赖batch/seq长度 |

**总显存公式**：

$$\text{显存(GB)} = \frac{(4 + 4 + 8)N + 2BSL \cdot d}{1024^3} = \frac{16N + 2BSL \cdot d}{1024^3}$$

其中：
- $N$：模型参数量
- $B$：批次大小
- $S$：序列长度
- $L$：层数
- $d$：隐藏维度

> **注**：激活值的计算公式是一个简化估计。对于Transformer解码器，由于KV-Cache的存在，实际激活值内存占用更接近 $BSLd + 2BSL^2$，在长序列下会显著增长。

#### 2.1.3 实际案例计算

**LLaMA-7B模型示例**：

参数设置：
- 参数量：$N = 7 \times 10^9$
- 批次大小：$B = 4$
- 序列长度：$S = 2048$
- 层数：$L = 32$
- 隐藏维度：$d = 4096$

**详细计算**：

$$\begin{align}
\text{模型参数} &= 4 \times 7 \times 10^9 = 28\text{GB} \\
\text{梯度} &= 4 \times 7 \times 10^9 = 28\text{GB} \\
\text{Adam状态} &= 8 \times 7 \times 10^9 = 56\text{GB} \\
\text{激活值} &= 2 \times 4 \times 2048 \times 32 \times 4096 \approx 2.1\text{GB} \\
\text{总计} &= 28 + 28 + 56 + 2.1 = 114.1\text{GB}
\end{align}$$

#### 2.1.4 优化技术的影响

**混合精度训练(FP16)**：

$$\text{显存优化} = \frac{(2 + 2 + 8)N + BSL \cdot d}{1024^3} = \frac{12N + BSL \cdot d}{1024^3}$$

节省约25%的显存。

**梯度检查点(Gradient Checkpointing)**：

$$\text{激活值优化} = \frac{\sqrt{L} \cdot BSd}{1024^3}$$

以计算时间换取显存空间，激活值显存减少约 $\sqrt{L}$ 倍。

**ZeRO优化器**：

$$\text{ZeRO-3显存} = \frac{16N/P + BSL \cdot d}{1024^3}$$

其中 $P$ 是GPU数量，实现近线性的显存缩放。

> **注**：此为理想情况下的计算公式。实际使用中，由于通信缓冲区和未分区参数的存在，显存占用会略高于理论值。

### 2.3 训练策略与最佳实践

#### 2.3.1 学习率调度策略

**余弦退火调度**：

$$\eta_t = \eta_{min} + \frac{1}{2}(\eta_{max} - \eta_{min})(1 + \cos(\frac{t\pi}{T}))$$

其中：
- $\eta_t$ 是第t步的学习率
- $\eta_{max}, \eta_{min}$ 是最大和最小学习率
- $T$ 是总训练步数

**线性预热策略**：

$$\eta_t = \begin{cases}
\eta_{max} \cdot \frac{t}{T_{warmup}} & \text{if } t \leq T_{warmup} \\
\eta_{schedule}(t) & \text{if } t > T_{warmup}
\end{cases}$$

#### 2.3.2 批次大小优化

**有效批次大小计算**：

$$\text{Effective Batch Size} = \text{Micro Batch Size} \times \text{Gradient Accumulation} \times \text{GPU Count}$$

**最优批次大小选择**：

```python
def find_optimal_batch_size(model, sample_input, max_memory_gb=40):
    """自动寻找最优批次大小"""
    batch_size = 1
    max_batch_size = 1

    while True:
        try:
            # 测试当前批次大小
            test_input = sample_input.repeat(batch_size, 1)

            torch.cuda.empty_cache()
            output = model(test_input)
            loss = output.loss
            loss.backward()

            # 检查显存使用
            memory_used = torch.cuda.memory_allocated() / 1024**3
            if memory_used < max_memory_gb * 0.9:
                max_batch_size = batch_size
                batch_size *= 2
            else:
                break

        except RuntimeError as e:
            if "out of memory" in str(e):
                break
            else:
                raise e

    return max_batch_size
```

## 3. 监督微调(SFT)深度解析

### 3.1 SFT基本原理

#### 3.1.1 定义与目标

**监督微调(Supervised Fine-Tuning, SFT)**是使用标注数据对预训练模型进行有监督训练的过程，目标是让模型学会遵循指令并生成高质量的回答。

**训练目标**：

$$\mathcal{L}_{SFT} = -\sum_{i=1}^{N} \sum_{t=1}^{T_i} \log P(y_t^{(i)} | x^{(i)}, y_{<t}^{(i)}; \theta)$$

其中：
- $N$ 是训练样本数量
- $x^{(i)}$ 是第i个输入指令
- $y^{(i)}$ 是对应的目标输出
- $\theta$ 是模型参数

#### 3.1.2 典型训练流程

**数据准备阶段**：

1. **指令构造**：
   ```
   输入：请解释什么是机器学习
   输出：机器学习是一种人工智能技术，通过算法让计算机从数据中学习模式...
   ```

2. **格式标准化**：
   ```json
   {
     "instruction": "请解释什么是机器学习",
     "input": "",
     "output": "机器学习是一种人工智能技术..."
   }
   ```

**训练阶段**：

```python
def sft_training_step(model, batch, optimizer):
    """SFT训练步骤"""
    # 构建输入序列
    input_ids = tokenizer(
        batch['instruction'] + batch['input'],
        return_tensors='pt'
    )

    # 构建目标序列
    target_ids = tokenizer(
        batch['output'],
        return_tensors='pt'
    )

    # 拼接输入和目标
    full_input = torch.cat([input_ids, target_ids], dim=1)

    # 创建标签（只对输出部分计算损失）
    labels = full_input.clone()
    labels[:, :len(input_ids)] = -100  # -100是PyTorch CrossEntropyLoss的默认忽略索引

    # 前向传播
    outputs = model(input_ids=full_input, labels=labels)
    loss = outputs.loss

    # 反向传播
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()

    return loss.item()
```

### 3.2 常见问题与解决方案

#### 3.2.1 灾难性遗忘问题

**问题描述**：
SFT过程中模型可能忘记预训练阶段学到的知识，导致在其他任务上性能下降。

**数学表达**：

$$\text{Forgetting} = \text{Performance}_{pretrain} - \text{Performance}_{after\_sft}$$

**解决方案**：

1. **知识蒸馏**：
   $$\mathcal{L}_{distill} = \alpha \mathcal{L}_{SFT} + (1-\alpha) \text{KL}(P_{teacher}, P_{student})$$

2. **弹性权重固化(EWC)**：
   $$\mathcal{L}_{EWC} = \mathcal{L}_{SFT} + \frac{\lambda}{2} \sum_i F_i (\theta_i - \theta_i^*)^2$$

3. **渐进式学习率**：
   ```python
   def progressive_learning_rate(epoch, base_lr=1e-5):
       """渐进式学习率调度"""
       if epoch < 5:
           return base_lr * 0.1  # 预热阶段
       elif epoch < 15:
           return base_lr        # 正常训练
       else:
           return base_lr * 0.1  # 稳定阶段
   ```

#### 3.2.3 过拟合问题

**检测方法**：

```python
def detect_overfitting(train_losses, val_losses, patience=5):
    """检测过拟合"""
    if len(val_losses) < patience:
        return False

    # 检查验证损失是否持续上升
    recent_val_losses = val_losses[-patience:]
    is_increasing = all(recent_val_losses[i] <= recent_val_losses[i+1]
                       for i in range(len(recent_val_losses)-1))

    # 检查训练损失是否持续下降
    recent_train_losses = train_losses[-patience:]
    is_decreasing = all(recent_train_losses[i] >= recent_train_losses[i+1]
                       for i in range(len(recent_train_losses)-1))

    return is_increasing and is_decreasing
```

**训练调度**：

```python
class CurriculumScheduler:
    def __init__(self, dataset, difficulty_fn):
        self.dataset = sorted(dataset, key=difficulty_fn)
        self.current_stage = 0
        self.stage_sizes = [0.3, 0.6, 1.0]  # 30%, 60%, 100%

    def get_current_data(self):
        """获取当前阶段的训练数据"""
        stage_ratio = self.stage_sizes[self.current_stage]
        end_idx = int(len(self.dataset) * stage_ratio)
        return self.dataset[:end_idx]

    def advance_stage():
        """进入下一阶段"""
        if self.current_stage < len(self.stage_sizes) - 1:
            self.current_stage += 1
```

## 4. 提示学习(Prompt Learning)

### 4.1 Prompt Tuning原理

#### 4.1.1 基本概念

**Prompt Tuning**是一种通过设计输入提示来激活预训练模型特定能力的轻量级调优方法，无需更新全部模型参数。

**核心思想**：
- 保持预训练模型参数固定
- 仅通过调整输入的提示文本引导模型生成所需输出
- 利用模型的上下文学习能力

**与传统微调的对比**：

| 对比维度 | Prompt Tuning | 传统Fine-Tuning |
|----------|---------------|------------------|
| 参数更新 | 仅优化提示部分(<1%) | 更新全部或大部分参数 |
| 计算成本 | 极低 | 高 |
| 数据需求 | 少量标注数据 | 大量标注数据 |
| 过拟合风险 | 低 | 高 |
| 任务适配 | 通过修改提示 | 需要重新训练 |

#### 4.1.2 数学原理

**传统微调目标**：

$$\min_\theta \mathcal{L}(\theta) = \sum_{i=1}^N \ell(f_\theta(x_i), y_i)$$

**Prompt Tuning目标**：

$$\min_P \mathcal{L}(P) = \sum_{i=1}^N \ell(f_{\theta_0}([P; x_i]), y_i)$$

其中：
- $\theta_0$ 是固定的预训练参数
- $P$ 是可学习的提示参数
- $[P; x_i]$ 表示提示和输入的拼接

### 4.2 硬提示与软提示

#### 4.2.1 硬提示(Hard Prompt)

**定义**：使用自然语言模板明确任务指令的提示方法。

**设计原则**：

1. **明确性**：指令清晰明确，避免歧义
2. **一致性**：同类任务使用相似的模板
3. **简洁性**：避免冗余信息

**典型模板**：

```python
# 情感分析模板
sentiment_template = """
请分析以下文本的情感倾向：

文本：{text}

情感：[正面/负面/中性]
"""

# 文本摘要模板
summary_template = """
请为以下文章生成简洁的摘要：

文章：{article}

摘要：
"""

# 问答模板
qa_template = """
基于以下上下文回答问题：

上下文：{context}

问题：{question}

答案：
"""
```

**优化策略**：

```python
def optimize_hard_prompt(templates, validation_data):
    """硬提示优化"""
    best_template = None
    best_score = 0

    for template in templates:
        scores = []
        for sample in validation_data:
            prompt = template.format(**sample)
            output = model.generate(prompt)
            score = evaluate_output(output, sample['target'])
            scores.append(score)

        avg_score = np.mean(scores)
        if avg_score > best_score:
            best_score = avg_score
            best_template = template

    return best_template, best_score
```

#### 4.2.2 软提示(Soft Prompt)

**定义**：将提示词替换为连续向量空间中的可学习嵌入。

**实现原理**：

$$\text{Input Embeddings} = [\text{Prompt Embeddings}; \text{Text Embeddings}]$$

**代码实现**：

```python
class SoftPromptTuning(nn.Module):
    def __init__(self, model, prompt_length=10, prompt_dim=768):
        super().__init__()
        self.model = model
        self.prompt_length = prompt_length

        # 初始化软提示嵌入
        self.soft_prompt = nn.Parameter(
            torch.randn(prompt_length, prompt_dim) * 0.1
        )

        # 冻结预训练模型参数
        for param in self.model.parameters():
            param.requires_grad = False

    def forward(self, input_ids, attention_mask=None):
        batch_size = input_ids.size(0)

        # 获取文本嵌入
        text_embeddings = self.model.get_input_embeddings()(input_ids)

        # 扩展软提示到批次维度
        prompt_embeddings = self.soft_prompt.unsqueeze(0).expand(
            batch_size, -1, -1
        )

        # 拼接提示和文本嵌入
        inputs_embeds = torch.cat([prompt_embeddings, text_embeddings], dim=1)

        # 调整注意力掩码
        if attention_mask is not None:
            prompt_mask = torch.ones(
                batch_size, self.prompt_length,
                device=attention_mask.device
            )
            attention_mask = torch.cat([prompt_mask, attention_mask], dim=1)

        # 前向传播
        outputs = self.model(
            inputs_embeds=inputs_embeds,
            attention_mask=attention_mask
        )

        return outputs
```

**训练过程**：

```python
def train_soft_prompt(model, dataloader, epochs=10):
    """软提示训练"""
    optimizer = torch.optim.AdamW(
        model.soft_prompt,
        lr=1e-3,
        weight_decay=0.01
    )

    for epoch in range(epochs):
        total_loss = 0

        for batch in dataloader:
            optimizer.zero_grad()

            outputs = model(
                input_ids=batch['input_ids'],
                attention_mask=batch['attention_mask']
            )

            # 计算损失（只对目标部分）
            loss = compute_loss(outputs.logits, batch['labels'])

            loss.backward()
            optimizer.step()

            total_loss += loss.item()

        print(f"Epoch {epoch+1}, Loss: {total_loss/len(dataloader):.4f}")
```

#### 4.2.3 混合提示策略

**组合方法**：

```python
class HybridPromptTuning(nn.Module):
    def __init__(self, model, hard_template, soft_prompt_length=5):
        super().__init__()
        self.model = model
        self.hard_template = hard_template
        self.soft_prompt_length = soft_prompt_length

        # 软提示嵌入
        self.soft_prompt = nn.Parameter(
            torch.randn(soft_prompt_length, model.config.hidden_size)
        )

    def forward(self, text_input):
        # 构建硬提示
        hard_prompt = self.hard_template.format(text=text_input)

        # 编码硬提示
        hard_tokens = tokenizer(hard_prompt, return_tensors='pt')
        hard_embeddings = self.model.get_input_embeddings()(hard_tokens.input_ids)

        # 插入软提示
        batch_size = hard_embeddings.size(0)
        soft_embeddings = self.soft_prompt.unsqueeze(0).expand(batch_size, -1, -1)

        # 组合嵌入
        combined_embeddings = torch.cat([
            soft_embeddings,
            hard_embeddings
        ], dim=1)

        return self.model(inputs_embeds=combined_embeddings)
```

#### 4.3.2 Few-shot Learning

**定义**：通过在输入中提供少量示例来指导模型完成任务。

**示例构建策略**：

```python
def construct_few_shot_prompt(examples, query, task_type="classification"):
    """构建少样本提示"""
    prompt_parts = []

    # 添加任务说明
    if task_type == "classification":
        prompt_parts.append("以下是一些分类示例：")
    elif task_type == "generation":
        prompt_parts.append("以下是一些生成示例：")

    # 添加示例
    for i, example in enumerate(examples):
        prompt_parts.append(f"\n示例{i+1}：")
        prompt_parts.append(f"输入：{example['input']}")
        prompt_parts.append(f"输出：{example['output']}")

    # 添加查询
    prompt_parts.append(f"\n现在请处理：")
    prompt_parts.append(f"输入：{query}")
    prompt_parts.append(f"输出：")

    return "\n".join(prompt_parts)
```

**示例选择策略**：

```python
def select_few_shot_examples(query, candidate_examples, k=3, method="similarity"):
    """选择最佳示例"""
    if method == "similarity":
        # 基于相似度选择
        similarities = []
        for example in candidate_examples:
            sim = calculate_similarity(query, example['input'])
            similarities.append((sim, example))

        # 选择最相似的k个
        similarities.sort(reverse=True)
        return [ex for _, ex in similarities[:k]]

    elif method == "diversity":
        # 基于多样性选择
        selected = []
        remaining = candidate_examples.copy()

        # 选择第一个（随机或最相似）
        first = max(remaining, key=lambda x: calculate_similarity(query, x['input']))
        selected.append(first)
        remaining.remove(first)

        # 选择剩余的，最大化多样性
        for _ in range(k-1):
            best_candidate = None
            best_diversity = -1

            for candidate in remaining:
                diversity = min(
                    calculate_diversity(candidate, selected_ex)
                    for selected_ex in selected
                )
                if diversity > best_diversity:
                    best_diversity = diversity
                    best_candidate = candidate

            if best_candidate:
                selected.append(best_candidate)
                remaining.remove(best_candidate)

        return selected
```

#### 4.3.3 In-Context Learning原理

**理论基础**：

大模型的上下文学习能力来源于：

1. **模式识别**：识别输入中的模式和规律
2. **类比推理**：基于示例进行类比
3. **任务理解**：理解任务的本质要求

**数学建模**：

$$P(y|x, \text{context}) = \text{softmax}(\text{Attention}(Q_x, K_{\text{context}}, V_{\text{context}}))$$

其中：
- $Q_x$ 是查询的表示
- $K_{\text{context}}, V_{\text{context}}$ 是上下文的键值表示

**影响因素分析**：

```python
def analyze_icl_factors(model, dataset, factors):
    """分析上下文学习影响因素"""
    results = {}

    for factor in factors:
        if factor == "example_count":
            # 测试示例数量的影响
            counts = [1, 2, 4, 8, 16]
            scores = []
            for count in counts:
                score = evaluate_with_examples(model, dataset, count)
                scores.append(score)
            results[factor] = dict(zip(counts, scores))

        elif factor == "example_order":
            # 测试示例顺序的影响

            scores = []
            for order in orders:
                score = evaluate_with_order(model, dataset, order)
                scores.append(score)
            results[factor] = dict(zip(orders, scores))

        elif factor == "prompt_format":
            # 测试提示格式的影响
            formats = ["qa", "completion", "instruction"]
            scores = []
            for fmt in formats:
                score = evaluate_with_format(model, dataset, fmt)
                scores.append(score)
            results[factor] = dict(zip(formats, scores))

```

## 5. 参数高效微调(PEFT)

### 5.1 LoRA技术详解

LoRA (Low-Rank Adaptation) 是一种革命性的参数高效微调技术，它允许我们在冻结预训练模型绝大部分参数的同时，高效地使其适应新任务。其核心思想是：模型在适应新任务时，其权重的变化是“低秩”的，即这种变化可以用远少于原始参数数量的参数来表示。

#### 5.1.1 核心原理：从“修改巨著”到“贴便签”

想象一下，一个预训练大模型就像一部内容浩瀚的百科全书（权重矩阵 $W_0$）。

-   **全参数微调**：相当于把整部百科全书重新抄写一遍，以修正少量词条来适应新主题。成本极高，且容易改错其他地方（灾难性遗忘）。
-   **LoRA**：则是在不改变原书任何内容的前提下，对需要修改的页面旁边贴上一张小小的“便签”（低秩适应矩阵 $\Delta W$）。这张便签上只记录了修改意见。查阅时，同时看原文和便签，就能得到更新后的内容。

**数学原理：**

LoRA的假设是，对于一个预训练的权重矩阵 $W_0 \in \mathbb{R}^{d \times k}$，微调后的新权重 $W$ 可以表示为：

$W = W_0 + \Delta W$

其中 $\Delta W$ 是参数的改变量。全参数微调会直接训练 $\Delta W$ 的所有 $d \times k$ 个参数。而LoRA的核心洞见是，$\Delta W$ 具有“低秩”结构，因此可以被分解为两个更小的矩阵的乘积：

$\Delta W = B \cdot A$

其中：
-   $A \in \mathbb{R}^{r \times k}$ 是一个“降维”矩阵。
-   $B \in \mathbb{R}^{d \times r}$ 是一个“升维”矩阵。
-   $r$ 是这个分解的“秩” (rank)，这是一个远小于 $d$ 和 $k$ 的超参数 ($r \ll \min(d, k)$)。

**训练过程的变化：**

在微调过程中，$W_0$ 保持冻结，我们**只训练**矩阵 $A$ 和 $B$ 的参数。

-   **原始计算**：模型的某一层前向传播为 $h = W_0 \cdot x$。
-   **LoRA计算**：前向传播变为 $h = W_0 \cdot x + \Delta W \cdot x = W_0 \cdot x + (B \cdot A) \cdot x$。

这个过程就像一个信息瓶颈：
1.  矩阵 $A$ 先将输入 $x$ 从 $k$ 维压缩到极低的 $r$ 维。
2.  矩阵 $B$ 再将这个 $r$ 维的表示恢复到 $d$ 维。
3.  最后将这个“修改量”加到原始的输出上。

**参数量对比：**

-   **原始 $\Delta W$ 参数量**：$d \times k$
-   **LoRA ($A$和$B$) 参数量**：$d \times r + r \times k = r(d+k)$

当 $r$ 很小时，LoRA的参数量相比原始参数量急剧减少。例如，对于一个 $4096 \times 4096$ 的权重矩阵和 $r=8$ 的配置，参数量从约1680万减少到仅约6.5万，压缩比超过250倍！

#### 5.1.3 超参数调优

**1. 秩 (r)**
-   **含义**：秩是信息瓶颈的大小，直接决定了LoRA适配器的参数量和表达能力。
-   **权衡**：
    -   **低 `r` (如 4, 8)**：参数少，训练快，正则化效果强，适合简单任务或防止过拟合。
    -   **高 `r` (如 32, 64)**：参数多，表达能力更强，可能在复杂任务上表现更好，但有更高的过拟合风险和显存占用。
-   **实践建议**：从 `r=16` 或 `r=8` 开始实验。研究表明，性能并非随 `r` 无限增长，通常在 `r=32` 或 `r=64` 之后会达到饱和甚至下降。

**2. Alpha (α)**
-   **含义**：LoRA的缩放因子。最终的权重增量 $\Delta W$ 会被乘以一个系数 `alpha / r`。
-   **权衡**：`alpha` 的作用类似于一个特殊的学习率。
    -   如果 `alpha = r`，则缩放系数为1。
    -   如果 `alpha > r`，则放大了LoRA权重的影响力。
-   **实践建议**：一个非常常见且有效的启发式设置是 `alpha = 2 * r`。例如，当 `r=16` 时，设置 `alpha=32`。这通常能取得比 `alpha=r` 更好的效果。可以将其视为一个可调优的超参数，但 `2*r` 是一个极佳的起点。

**3. 目标模块 (target_modules)**
-   **含义**：指定在模型的哪些部分应用LoRA。
-   **实践建议**：
    -   **标准选择**：对于大多数Transformer模型，将LoRA应用于注意力机制中的**查询(query)**和**值(value)**投影层（即 `q_proj` 和 `v_proj`）是性价比最高的选择，能在最少的参数下获得最好的效果。
    -   **扩展选择**：为了获得更强的性能，可以尝试将LoRA应用到更多的线性层，如 `k_proj` (key), `o_proj` (output)，甚至是前馈网络(FFN)中的 `gate_proj`, `up_proj`, `down_proj`。这会增加可训练参数，但有时能带来显著的性能提升。
    -   **如何查找**：如果不确定模块名称，可以打印出 `model` 的结构来查看所有线性层的名称。


### 5.2 其他PEFT方法

#### 5.2.1 Adapter方法

**基本结构**：

```python
class AdapterLayer(nn.Module):
    def __init__(self, hidden_size, adapter_size=64):
        super().__init__()
        self.down_project = nn.Linear(hidden_size, adapter_size)
        self.activation = nn.ReLU()
        self.up_project = nn.Linear(adapter_size, hidden_size)
        self.dropout = nn.Dropout(0.1)

    def forward(self, x):
        # 下投影
        h = self.down_project(x)
        h = self.activation(h)
        h = self.dropout(h)

        # 上投影
        h = self.up_project(h)

        # 残差连接
        return x + h

class TransformerWithAdapter(nn.Module):
    def __init__(self, original_transformer, adapter_size=64):
        super().__init__()
        self.transformer = original_transformer

        # 在每个Transformer层后添加Adapter
        for layer in self.transformer.layers:
            layer.adapter = AdapterLayer(
                layer.hidden_size,
                adapter_size
            )

    def forward(self, x):
        for layer in self.transformer.layers:
            # 原始Transformer计算
            x = layer.attention(x)
            x = layer.feed_forward(x)

            # Adapter计算
            x = layer.adapter(x)

        return x
```

#### 5.2.2 Prefix Tuning

**原理**：在每一层的键值对前添加可训练的前缀。

```python
class PrefixTuning(nn.Module):
    def __init__(self, model, prefix_length=10, num_layers=12):
        super().__init__()
        self.model = model
        self.prefix_length = prefix_length
        self.num_layers = num_layers

        # 前缀参数
        self.prefix_tokens = nn.Parameter(
            torch.randn(num_layers, 2, prefix_length, model.config.hidden_size)
        )

        # 冻结原模型参数
        for param in model.parameters():
            param.requires_grad = False

    def forward(self, input_ids, attention_mask=None):
        batch_size = input_ids.size(0)

        # 扩展前缀到批次维度
        prefix_keys_values = self.prefix_tokens.unsqueeze(0).expand(
            batch_size, -1, -1, -1, -1
        )

        # 修改模型的前向传播以使用前缀
        return self.model.forward_with_prefix(
            input_ids=input_ids,
            attention_mask=attention_mask,
            prefix_keys_values=prefix_keys_values
        )
```

## 6. 微调优化技术

### 6.1 梯度优化策略

#### 6.1.1 梯度累积

**原理**：

梯度累积是一种在不增加显存消耗的情况下，模拟大批量（Large Batch Size）训练的技巧。其核心思想是：将大批次的数据拆分成多个小批次（Micro-batch），依次通过模型计算每个小批次的梯度，但**暂不更新模型参数**。而是将这些小批次的梯度在内存中不断累加，直到达到指定的小批次数量后，再用累积的总梯度来更新一次模型参数。

从数学上看，这利用了梯度计算的线性特性。假设一个大批次的损失函数 $\mathcal{L}$ 是由 $K$ 个小批次的损失函数 $\mathcal{L}_k$ 之和构成的：

$$\mathcal{L} = \sum_{k=1}^{K} \mathcal{L}_k$$

那么，对参数 $\theta$ 的总梯度等于每个小批次梯度之和：

$$\nabla_\theta \mathcal{L} = \nabla_\theta \left(\sum_{k=1}^{K} \mathcal{L}_k\right) = \sum_{k=1}^{K} \nabla_\theta \mathcal{L}_k$$

因此，通过累积 $K$ 个小批次的梯度，我们得到的结果与直接计算一个大小为 $K$ 倍的大批次的梯度是等价的。这使得我们能用有限的显存实现大批量训练，从而提高训练的稳定性和模型性能。

**实现方法**：

实现梯度累积的关键在于控制 `optimizer.step()` 和 `optimizer.zero_grad()` 的调用时机。

1.  **初始化**：在训练循环开始前，正常初始化模型、优化器和数据加载器。
2.  **循环累积**：在训练循环中，设置一个累积步数 `accumulation_steps`。
3.  **损失归一化**：在每次前向传播计算损失后，将损失值除以 `accumulation_steps`。这是非常关键的一步，因为我们最终要的是梯度的平均值，而不是总和，以保证学习率的尺度正确。
4.  **梯度反向传播**：调用 `loss.backward()`。PyTorch的特性是，每次调用 `backward()` 都会将计算出的梯度**累加**到参数的 `.grad` 属性上，而不是覆盖。
5.  **条件更新**：通过一个计数器判断是否达到了累积步数。
    -   如果未达到，则继续下一个小批次的计算。
    -   如果达到了 `accumulation_steps`，则执行参数更新。
6.  **参数更新与梯度清零**：
    -   （可选但推荐）执行梯度裁剪，防止梯度爆炸。
    -   调用 `optimizer.step()`，使用累积的梯度更新模型参数。
    -   调用 `optimizer.zero_grad()`，清空累积的梯度，为下一次累积做准备。

**实现代码**：

```python
def gradient_accumulation_training(model, dataloader, optimizer, accumulation_steps=4):
    """梯度累积训练的详细实现"""
    model.train()
    optimizer.zero_grad()  # 在循环外部先清零一次
    total_loss = 0

    for i, batch in enumerate(dataloader):
        # 1. 前向传播
        outputs = model(batch)
        loss = outputs.loss

        # 2. 关键：损失归一化
        # 这是为了保证当累积了N次梯度后，其平均值与单个大批次的梯度幅度相当
        loss = loss / accumulation_steps

        # 3. 反向传播，梯度会累积
        loss.backward()
        total_loss += loss.item() # 记录的是归一化后的损失

        # 4. 每 accumulation_steps 步更新一次参数
        if (i + 1) % accumulation_steps == 0:
            # (可选) 梯度裁剪
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

            # 5. 参数更新
            optimizer.step()

            # 6. 清空梯度，为下一次累积做准备
            optimizer.zero_grad()

    # 返回的是累积了N步的总损失，乘以accumulation_steps可得到等效的单步损失
    return total_loss * accumulation_steps
```

#### 6.1.2 梯度裁剪

**为什么需要梯度裁剪？**

在深度神经网络（尤其是RNN和Transformer）的训练过程中，有时会遇到**梯度爆炸（Gradient Exploding）**的问题。这指的是梯度值变得异常巨大，导致模型参数更新步子迈得太大，跳过了最优解，甚至可能导致数值溢出（NaN），最终使训练过程完全发散。梯度裁剪是一种简单而有效的技术，通过限制梯度的最大范数（magnitude）来防止梯度爆炸，从而稳定训练过程。

**全局梯度裁剪 (Global Gradient Clipping)**

这是最常用的一种梯度裁剪方法。它计算模型**所有**参数的梯度的总体范数（通常是L2范数），然后将这个总范数与一个预设的阈值 $\tau$ (tau)进行比较。

-   如果总范数小于或等于 $\tau$，则保持梯度不变。
-   如果总范数大于 $\tau$，则按比例缩小**所有**梯度，使得它们的总范数恰好等于 $\tau$。

**数学表达**：

令 $g$ 为所有参数梯度的向量拼接。全局梯度范数 $||g|| = \sqrt{\sum_i (\nabla_\theta \mathcal{L}_i)^2}$。裁剪后的梯度 $\hat{g}$ 为：

$$\hat{g} = \begin{cases}
g & \text{if } ||g|| \leq \tau \\
\frac{\tau}{||g||} g & \text{if } ||g|| > \tau
\end{cases}$$

**核心思想**：这种方法保持了梯度更新的**方向**，只调整了更新的**步长**（幅度）。它确保了单次更新不会过大，但缺点是需要选择一个合适的超参数 $\tau$。如果 $\tau$太大，裁剪不起作用；如果 $\tau$太小，会限制模型的学习能力。

**Pytorch实现**：

```python
# 在 optimizer.step() 之前调用
max_norm = 1.0 # 这是一个常用的超参数值
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=max_norm)
```

**自适应梯度裁剪 (Adaptive Gradient Clipping)**

全局梯度裁剪的一个痛点是固定的阈值 $\tau$ 可能不适用于所有训练阶段或所有模型。自适应梯度裁剪旨在解决这个问题，它动态地调整裁剪阈值，而不是使用一个固定的值。

**原理**：

它不再观察全局的梯度范数，而是关注**每个参数（或每层）的权重范数与梯度范数之间的比率**。其核心假设是：在一个训练良好的模型中，权重范数 $||W||$ 和其对应的梯度范数 $||\nabla W||$ 应该保持一个相对稳定的比率。

如果某个梯度范数 $||\nabla W||$ 相对于其权重范数 $||W||$ 异常地大，就说明这次更新可能是不稳定的。因此，自适应裁剪会根据这个比率来决定是否裁剪梯度。

**实现流程**：

1.  对于模型中的每一个参数（或每一层），分别计算其权重范数 $||W||$ 和梯度范数 $||\nabla W||$。
2.  计算比率：$\lambda = \frac{||\nabla W||}{||W||}$。
3.  如果这个比率 $\lambda$ 超过了预设的阈值 $\epsilon$ (epsilon)，则对该参数的梯度进行裁剪，使其范数满足：$||\nabla W_{clipped}|| = \epsilon \cdot ||W||$。

**优势**：

-   **无需手动设置阈值**：它根据模型自身的状态（权重大小）来动态决定裁剪幅度。
-   **更精细的控制**：它对模型的不同部分应用不同的裁剪强度，而不是“一刀切”。

**实现代码** (简化版示例)：

```python
class AdaptiveGradientClipper:
    def __init__(self, clip_factor=0.01, eps=1e-3):
        self.clip_factor = clip_factor
        self.eps = eps

    def clip_gradients(self, model):
        """自适应梯度裁剪"""
        for p in model.parameters():
            if p.grad is not None:
                # 计算权重范数和梯度范数
                w_norm = p.data.norm(2)
                g_norm = p.grad.data.norm(2)

                # 计算裁剪阈值
                max_norm = w_norm * self.clip_factor

                # 如果梯度范数超过阈值，则进行裁剪
                if g_norm > max_norm:
                    clip_coef = max_norm / (g_norm + self.eps)
                    p.grad.data.mul_(clip_coef)
```

**总结对比**：

| 特性 | 全局梯度裁剪 | 自适应梯度裁剪 |
| :--- | :--- | :--- |
| **作用对象** | 所有参数的梯度总和 | 单个参数（或层）的梯度 |
| **裁剪依据** | 固定的全局范数阈值 $\tau$ | 权重范数与梯度范数的比率 |
| **优点** | 实现简单，Pytorch内置 | 无需手动调参，更精细 |
| **缺点** | 阈值 $\tau$ 难以选择 | 计算稍复杂，对权重初始化敏感 |

#### 6.1.3 学习率调度

**余弦退火调度**：

```python
class CosineAnnealingWithWarmup:
    def __init__(self, optimizer, warmup_steps, total_steps, min_lr=1e-6):
        self.optimizer = optimizer
        self.warmup_steps = warmup_steps
        self.total_steps = total_steps
        self.min_lr = min_lr
        self.base_lr = optimizer.param_groups[0]['lr']
        self.current_step = 0

    def step(self):
        """更新学习率"""
        self.current_step += 1

        if self.current_step <= self.warmup_steps:
            # 线性预热
            lr = self.base_lr * self.current_step / self.warmup_steps
        else:
            # 余弦退火
            progress = (self.current_step - self.warmup_steps) / (self.total_steps - self.warmup_steps)
            lr = self.min_lr + (self.base_lr - self.min_lr) * 0.5 * (1 + math.cos(math.pi * progress))

        for param_group in self.optimizer.param_groups:
            param_group['lr'] = lr

        return lr
```

**分层学习率**：

```python
def create_layerwise_optimizer(model, base_lr=1e-4, decay_rate=0.9):
    """创建分层学习率优化器"""
    param_groups = []

    # 获取层数
    num_layers = len(list(model.named_modules()))

    for i, (name, param) in enumerate(model.named_parameters()):
        if param.requires_grad:
            # 计算层级
            layer_depth = name.count('.')

            # 计算学习率
            lr = base_lr * (decay_rate ** (num_layers - layer_depth))

            param_groups.append({
                'params': [param],
                'lr': lr,
                'name': name
            })

    return torch.optim.AdamW(param_groups)
```

### 6.2 正则化技术

#### 6.2.1 权重衰减与L2正则化

**原理详解**：

**L2正则化**和**权重衰减(Weight Decay)**是两种最常见的正则化技术，旨在防止模型过拟合。它们的目标都是通过惩罚过大的模型权重，来鼓励模型学习更简单、更泛化的模式。

-   **L2正则化**: 直接在损失函数上添加一个惩罚项，该惩罚项正比于所有权重平方和。
    $$\mathcal{L}_{total} = \mathcal{L}_{task} + \frac{\lambda}{2} \sum_{i} \theta_i^2$$
    当使用梯度下降法时，这个惩罚项对梯度的贡献是 $\lambda \theta_i$。因此，参数更新变为：
    $$\theta_{t+1} = \theta_t - \eta (\nabla_{\theta_t}\mathcal{L}_{task} + \lambda \theta_t)$$

-   **权重衰减**: 直接在参数更新规则中，将权重向零的方向“衰减”一个小的比例，然后再减去梯度。
    $$\theta_{t+1} = \theta_t - \eta \nabla_{\theta_t}\mathcal{L}_{task} - \eta \lambda' \theta_t = (1 - \eta \lambda')\theta_t - \eta \nabla_{\theta_t}\mathcal{L}_{task}$$

**两者关系**：
在标准的SGD优化器中，L2正则化和权重衰减是等价的（令 $\lambda' = \lambda$）。但在自适应学习率优化器（如Adam）中，它们**不等价**。Adam会对梯度进行缩放，如果L2正则化的梯度项也被缩放，效果就会打折扣。因此，**AdamW**被提出来，它将权重衰减步骤与梯度更新步骤解耦，实现了真正的权重衰减，这在NLP微调中是首选。

**NLP中的实现**：
在Hugging Face `Trainer` 或 `torch.optim.AdamW` 中，直接设置 `weight_decay` 参数即可。通常，我们只对权重矩阵应用衰减，而不对偏置（bias）和层归一化（LayerNorm）的参数应用，因为这可能会损害性能。

```python
# AdamW是最常用的选择
from torch.optim import AdamW

# 将参数分为两组：应用衰减的和不应用衰减的
decay_params = [p for n, p in model.named_parameters() if "bias" not in n and "LayerNorm.weight" not in n]
no_decay_params = [p for n, p in model.named_parameters() if "bias" in n or "LayerNorm.weight" in n]

optimizer_grouped_parameters = [
    {'params': decay_params, 'weight_decay': 0.01},
    {'params': no_decay_params, 'weight_decay': 0.0}
]

optimizer = AdamW(optimizer_grouped_parameters, lr=1e-5)
```

**自适应权重衰减**：

**原理**：
标准的权重衰减对所有参数“一视同仁”，但模型中的不同参数重要性不同。自适应权重衰减的核心思想是：**对越重要的参数，施加越小的惩罚**。

**如何衡量重要性？**
一个常用的代理指标是参数在训练过程中的**梯度大小**。如果一个参数的梯度一直很大，说明它对模型降低损失至关重要。

**实现**：
下面的代码通过计算每个参数梯度的平均绝对值来估计其重要性，然后根据重要性反向调整权重衰减的强度。

```python
class AdaptiveWeightDecay:
    def __init__(self, model, base_decay=0.01):
        self.model = model
        self.base_decay = base_decay
        self.param_importance = {}

    def compute_importance(self, dataloader):
        """计算参数重要性（例如，在验证集上计算）"""
        self.model.eval()
        # 初始化重要性字典
        for name, param in self.model.named_parameters():
            if param.requires_grad:
                self.param_importance[name] = 0

        # 累积梯度以评估重要性
        for batch in dataloader:
            outputs = self.model(batch)
            loss = outputs.loss
            grads = torch.autograd.grad(loss, self.model.parameters(), retain_graph=True)
            for (name, param), grad in zip(self.model.named_parameters(), grads):
                if param.requires_grad:
                    self.param_importance[name] += grad.abs().mean().item()
        
        # 归一化重要性
        max_importance = max(self.param_importance.values()) if self.param_importance else 1.0
        for name in self.param_importance:
            self.param_importance[name] /= max_importance

    def apply_decay(self, optimizer):
        """在优化器步骤中应用自适应权重衰减"""
        for group in optimizer.param_groups:
            for param in group['params']:
                if param.grad is not None:
                    param_name = self.get_param_name(param) # 需要一个辅助函数来获取参数名
                    importance = self.param_importance.get(param_name, 0.5) # 默认为中等重要性

                    # 重要参数使用较小的衰减 (1 - importance)
                    decay = self.base_decay * (1.0 - importance)
                    param.data.mul_(1.0 - group['lr'] * decay)
```

#### 6.2.2 Dropout策略

**原理与对比**

Dropout是一种强大的正则化技术，其核心思想是在训练过程中引入随机性，以防止神经元之间的“共适应”现象，从而增强模型的泛化能力。

-   **标准Dropout**: 
    -   **作用对象**: **激活（Activations）**。在一次前向传播中，它以概率 `p` 将一个层中某些神经元的输出（激活值）随机置为零。
    -   **效果**: 相当于在每次训练迭代中，都在训练一个不同的、“瘦身”版的子网络。最终的模型可以看作是这些无数子网络的集成，从而变得更加鲁棒。
    -   **类比**: 团队合作中，每次开会都随机让几个人“禁言”。为了完成任务，其他人必须学会承担更多的责任，不能过度依赖某几个核心成员。这使得整个团队的能力更加均衡和强大。

-   **DropConnect**: 
    -   **作用对象**: **权重（Weights）**。它不是将神经元的输出置零，而是以概率 `p` 将连接神经元的权重（即`W`矩阵中的元素）置零。
    -   **与Dropout的区别**: Dropout作用在层的输出上，而DropConnect作用在层的内部连接上。因此，DropConnect可以看作是Dropout的一种更泛化的形式。如果一个神经元的所有输入连接都被DropConnect置零，那它的效果就等同于被Dropout。但DropConnect可以创造出更丰富的稀疏连接模式。
    -   **为何是优化**: 它创造了一个比Dropout大得多的子网络集成。Dropout的子网络数量是 $2^N$（N是神经元数量），而DropConnect的子网络数量是 $2^M$（M是连接/权重数量），通常 $M \gg N$。这能带来更强的正则化效果，但计算成本也略高。

-   **自适应Dropout**: 
    -   **本质**: 这不是一种新的Dropout机制，而是一种**Dropout调度策略**。它主张Dropout的概率 `p` 不应在整个训练过程中保持不变，而应动态调整。
    -   **为何是优化**: 模型的训练阶段不同，最优的正则化强度也不同。
        -   **早期训练**: 模型还在学习基本特征，过强的Dropout（高`p`值）可能会干扰学习过程。
        -   **后期训练**: 模型基本收敛，容易在训练数据上过拟合，此时增强Dropout（高`p`值）可以有效抑制过拟合。
    -   **实现策略**: 可以设计一个关于训练步数的函数来控制`p`。例如，训练初期使用较小的`p`，然后逐渐增大。下面的代码实现了一种“预热后退火”的策略：`p`在训练初期较大，鼓励模型探索，然后逐渐降低到基准值。

**实现代码**：

```python
# 自适应Dropout: 动态调整p值
class AdaptiveDropout(nn.Module):
    def __init__(self, base_p=0.1, total_steps=10000):
        super().__init__()
        self.base_p = base_p
        self.total_steps = total_steps
        self.training_step = 0

    def forward(self, x):
        if not self.training:
            return x

        # 示例策略：训练前期p较小，后期增大
        progress = min(self.training_step / self.total_steps, 1.0)
        current_p = self.base_p * (1 + progress) / 2 # 从 p/2 线性增长到 p
        
        self.training_step += 1
        return F.dropout(x, p=current_p, training=self.training)

# DropConnect: 对权重进行Dropout
class DropConnect(nn.Module):
    def __init__(self, linear_layer, drop_prob=0.1):
        super().__init__()
        self.linear = linear_layer
        self.drop_prob = drop_prob

    def forward(self, x):
        if not self.training or self.drop_prob == 0:
            return self.linear(x)

        # 对权重矩阵应用mask
        # .bernoulli_() 是原地操作
        mask = torch.ones_like(self.linear.weight).bernoulli_(1 - self.drop_prob)
        
        # 在推理时需要缩放，训练时也缩放以保持期望一致
        weight = self.linear.weight * mask / (1 - self.drop_prob)

        return F.linear(x, weight, self.linear.bias)
```

### 6.3 评估与监控

对微调过程进行细致的评估与监控，是确保模型质量、诊断训练问题、防止过拟合以及最终达成预期目标的关键环节。没有有效的监控，训练过程就像在“黑箱”中航行，既不知道方向是否正确，也无法判断何时到达目的地。

-   **训练监控 (Training Monitoring)**：实时观察模型在训练过程中的“健康状况”，例如损失是否下降、梯度是否稳定。这有助于我们及时发现并解决问题，如学习率设置不当、梯度爆炸或消失等。
-   **性能评估 (Performance Evaluation)**：在独立的验证集或测试集上，根据特定任务的指标（如准确率、BLEU分数）来衡量模型真正的泛化能力。这是判断微调是否成功的最终标准。

#### 6.3.1 训练监控

训练监控的核心是跟踪一系列关键指标，通过它们的变化趋势来理解模型的学习动态。

**关键监控指标解读**：

| 指标 | 监控目的 | 正常现象 | 异常信号与对策 |
| :--- | :--- | :--- | :--- |
| **损失 (Loss)** | 衡量模型预测与真实标签的差距 | 训练集和验证集损失都平稳下降并收敛 | 1. **训练损失不降**：学习率过低、模型结构问题、数据问题。<br>2. **验证损失上升**：过拟合，需增加正则化、早停或更多数据。<br>3. **损失剧烈震荡**：学习率过高，可降低学习率或使用梯度裁剪。 |
| **学习率 (LR)** | 确认学习率调度器是否按预期工作 | 曲线与调度策略（如预热、余弦退火）一致 | 曲线为一条直线（调度器未生效）或变化不符合预期。 |
| **梯度范数 (Grad Norm)** | 衡量全体梯度的大小，判断训练稳定性 | 保持在一个相对稳定的范围内 | 1. **范数激增 (梯度爆炸)**：导致训练不稳定，需使用梯度裁剪。<br>2. **范数趋近于0 (梯度消失)**：模型难以学习，可尝试残差连接、Normalization或更换激活函数。 |
| **参数范数 (Param Norm)** | 衡量模型所有参数的大小 | 随训练平稳增长后趋于稳定 | 参数范数持续无限制增长，可能预示着模型不稳定或过拟合。 |
| **显存使用 (Memory)** | 监控硬件资源利用率 | 稳定在GPU显存容量以下 | 显存溢出（OOM），需减小批次大小、序列长度或使用显存优化技术（如梯度累积、ZeRO）。 |

**实现代码**：

一个监控器类可以方便地集成到训练循环中，定期收集和记录这些指标。

```python
import torch
import numpy as np

class TrainingMonitor:
    """一个用于在训练期间收集和记录关键指标的监控器。"""
    def __init__(self, model, log_interval=100):
        self.model = model
        self.log_interval = log_interval
        self.metrics = {
            'loss': [],
            'learning_rate': [],
            'gradient_norm': [],
            'parameter_norm': [],
            'memory_usage_gb': []
        }

    def log_step(self, step, loss, optimizer):
        """在每个训练步骤后调用，以记录指标。"""
        if step % self.log_interval == 0:
            # 记录标量损失
            self.metrics['loss'].append(loss)

            # 记录当前学习率
            lr = optimizer.param_groups[0]['lr']
            self.metrics['learning_rate'].append(lr)

            # 计算并记录梯度的L2范数
            grad_norm = self.compute_gradient_norm()
            if grad_norm is not None:
                self.metrics['gradient_norm'].append(grad_norm)

            # 计算并记录参数的L2范数
            param_norm = self.compute_parameter_norm()
            self.metrics['parameter_norm'].append(param_norm)

            # 记录已分配的GPU显存（以GB为单位）
            memory_usage = torch.cuda.memory_allocated() / 1024**3
            self.metrics['memory_usage_gb'].append(memory_usage)

    def compute_gradient_norm(self):
        """计算模型所有参数的梯度总范数。"""
        total_norm = 0.0
        for p in self.model.parameters():
            if p.grad is not None:
                param_norm = p.grad.data.norm(2)
                total_norm += param_norm.item() ** 2
        return total_norm ** 0.5 if total_norm > 0 else None

    def compute_parameter_norm(self):
        """计算模型所有参数的总范数。"""
        total_norm = 0.0
        for p in self.model.parameters():
            param_norm = p.data.norm(2)
            total_norm += param_norm.item() ** 2
        return total_norm ** 0.5

    def plot_metrics(self):
        """可视化所有记录的指标（需要 matplotlib）。"""
        import matplotlib.pyplot as plt
        num_metrics = len(self.metrics)
        fig, axes = plt.subplots(num_metrics, 1, figsize=(10, num_metrics * 4))
        for i, (name, values) in enumerate(self.metrics.items()):
            if values:
                axes[i].plot(values)
                axes[i].set_title(name)
                axes[i].set_xlabel(f"Logged Steps (x{self.log_interval})")
                axes[i].set_ylabel("Value")
        plt.tight_layout()
        plt.show()
```

#### 6.3.2 性能评估

当训练监控显示模型已收敛时，我们需要在独立的验证集或测试集上进行性能评估，以客观地衡量模型的泛化能力。

**选择合适的评估指标**

评估指标的选择与具体任务强相关。

-   **分类任务 (Classification)**:
    -   **准确率 (Accuracy)**: 最直观的指标，即正确分类的样本占总样本的比例。适用于类别均衡的数据集。
    -   **精确率 (Precision)**: 在所有被预测为正类的样本中，真正是正类的比例。关注“查准”。
    -   **召回率 (Recall)**: 在所有真正的正类样本中，被成功预测为正类的比例。关注“查全”。
    -   **F1分数 (F1-Score)**: 精确率和召回率的调和平均数，是评估分类模型综合性能的常用指标。

-   **生成任务 (Generation)**:
    -   **BLEU**: 主要用于机器翻译，通过比较生成文本与参考文本之间n-gram的重合度来评估质量。
    -   **ROUGE**: 主要用于文本摘要，通过比较n-gram、最长公共子序列等来衡量生成摘要与参考摘要的重合度。
    -   **Perplexity (PPL)**: 语言模型的固有评估指标，衡量模型对一个句子的不确定性。PPL越低，说明模型对句子的概率分布预测得越好，语言模型能力越强。
    -   **人工评估/模型评估**: 对于复杂的生成任务（如对话、创意写作），传统指标往往无法捕捉语义和逻辑的质量。此时，人工评估是金标准。近年来，使用更强的模型（如GPT-4）作为裁判来进行模型评估也成为一种高效的替代方案。

**实现代码**：

一个评估器类可以封装不同任务的评估逻辑。

```python
from sklearn.metrics import accuracy_score, f1_score
from nltk.translate.bleu_score import corpus_bleu

class PerformanceEvaluator:
    """封装了针对不同任务的模型性能评估逻辑。"""
    def __init__(self, metrics=['accuracy', 'f1', 'bleu']):
        self.metrics = metrics

    def evaluate(self, model, tokenizer, dataloader, task_type='classification'):
        """
        在给定的数据集上全面评估模型性能。

        Args:
            model: 要评估的模型。
            tokenizer: 用于解码生成结果的分词器。
            dataloader: 包含评估数据的Dataloader。
            task_type: 'classification' 或 'generation'。
        """
        model.eval()
        all_predictions = []
        all_targets = []

        with torch.no_grad():
            for batch in dataloader:
                # 将数据移动到模型所在设备
                inputs = {k: v.to(model.device) for k, v in batch.items() if k != 'labels'}
                targets = batch['labels']

                if task_type == 'classification':
                    outputs = model(**inputs)
                    preds = torch.argmax(outputs.logits, dim=-1)
                    all_predictions.extend(preds.cpu().numpy())
                    all_targets.extend(targets.cpu().numpy())
                
                elif task_type == 'generation':
                    # 对于生成任务，'inputs' 通常只包含 'input_ids' 和 'attention_mask'
                    generated_ids = model.generate(
                        input_ids=inputs['input_ids'],
                        attention_mask=inputs['attention_mask'],
                        max_new_tokens=50 # 限制生成长度
                    )
                    # 解码生成结果和目标结果
                    decoded_preds = tokenizer.batch_decode(generated_ids, skip_special_tokens=True)
                    decoded_targets = tokenizer.batch_decode(targets, skip_special_tokens=True)
                    all_predictions.extend(decoded_preds)
                    all_targets.extend(decoded_targets)

        # 根据任务类型计算指标
        results = {}
        if task_type == 'classification':
            if 'accuracy' in self.metrics:
                results['accuracy'] = accuracy_score(all_targets, all_predictions)
            if 'f1' in self.metrics:
                results['f1'] = f1_score(all_targets, all_predictions, average='weighted')
        
        elif task_type == 'generation':
            if 'bleu' in self.metrics:
                results['bleu'] = self.compute_bleu(all_predictions, all_targets)
        
        return results

    def compute_bleu(self, predictions, references):
        """计算BLEU分数。注意：需要将字符串转换为token列表。"""
        # NLTK的corpus_bleu期望一个引用列表的列表
        # e.g., [[ref1_tokens, ref2_tokens], [ref_tokens], ...]
        ref_tokens = [[ref.split()] for ref in references]
        pred_tokens = [pred.split() for pred in predictions]
        return corpus_bleu(ref_tokens, pred_tokens)
```

- 训练损失持续下降，验证损失上升

**原因分析**：

```python
def analyze_overfitting(train_history, val_history):
    """分析过拟合程度"""
    # 计算训练验证差距
    gap = np.array(val_history) - np.array(train_history)

    # 检测过拟合开始点
    overfitting_start = None
    for i in range(1, len(gap)):
        if gap[i] > gap[i-1] and gap[i] > 0.1:
            overfitting_start = i
            break

    # 计算过拟合严重程度
    if overfitting_start:
        severity = np.mean(gap[overfitting_start:])
        return {
            'overfitting': True,
            'start_epoch': overfitting_start,
            'severity': severity
        }

    return {'overfitting': False}
```

#### 7.2.2 灾难性遗忘案例

**问题描述**：
在特定任务上微调后，模型在其他任务上的性能显著下降。

**量化分析**：

```python
def measure_catastrophic_forgetting(model_before, model_after, test_tasks):
    """量化灾难性遗忘程度"""
    forgetting_scores = {}

    for task_name, task_data in test_tasks.items():
        # 微调前性能
        score_before = evaluate_model(model_before, task_data)

        # 微调后性能
        score_after = evaluate_model(model_after, task_data)

        # 计算遗忘程度
        forgetting = (score_before - score_after) / score_before
        forgetting_scores[task_name] = forgetting

    return forgetting_scores
```

**缓解策略**：

1. **弹性权重固化**：
   - 在微调时，对那些对旧任务重要的参数施加一个惩罚，使其变化不大。
   - 重要性通常用费雪信息矩阵(Fisher Information Matrix)来衡量。

2. **多任务学习**:
   - 在微调时，混合新旧任务的数据，让模型同时学习。

3. **使用PEFT方法**:
   - LoRA等PEFT方法本身就能有效缓解灾难性遗忘，因为它们只修改模型的一小部分，大部分预训练知识得以保留。

### 7.3 最新进展

- **QLoRA**: 4-bit量化与LoRA的结合，进一步降低了微调的显存门槛。
- **DoRA (Weight-Decomposed Low-Rank Adaptation)**: 将预训练权重分解为大小和方向两部分，并对两者分别使用LoRA进行微调，取得了比LoRA更好的效果。
- **AdaLoRA**: 一种自适应的LoRA方法，可以根据参数的重要性动态分配秩，使得重要的权重更新有更高的秩，不重要的权重更新有更低的秩。
