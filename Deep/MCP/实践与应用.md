### 1. 环境搭建与工具链

由于 MCP 是一个较新的协议，可能还没有官方的、功能完备的库。但我们可以轻易地使用现有工具来实现它。

*   **服务端 (Provider)**: 我们选用 `fastapi`，因为它性能高、支持异步，且数据校验功能强大。
*   **客户端 (Client)**: 我们选用 `httpx`，它是一个现代、支持异步的 HTTP 客户端。

**安装所需库:**

### 2. 服务端实现 (Model Provider)

我们将创建一个简单的、基于内存存储的 MCP 模型提供方。

**文件: `mcp_provider.py`**

```python
import uvicorn
from fastapi import FastAPI, Request, HTTPException
from pydantic import BaseModel, Field
from typing import List, Dict, Any, Optional
import uuid

# --- 1. Pydantic 模型定义 (数据校验) ---
# 使用 Pydantic 模型可以自动校验传入的 JSON 数据是否符合 MCP 规范

class ContextItem(BaseModel):
    item_id: str
    content_type: str
    content: Any

class ContextUpdatePayload(BaseModel):
    add: Optional[List[ContextItem]] = None
    update: Optional[List[ContextItem]] = None
    remove: Optional[List[str]] = None

class ModelRequestPayload(BaseModel):
    prompt: str
    context_item_ids: Optional[List[str]] = None
    parameters: Optional[Dict[str, Any]] = None
    stream: Optional[bool] = False

class MCPMessage(BaseModel):
    protocol_version: str
    message_id: str
    message_type: str
    payload: Dict[str, Any]

# --- 2. 服务端核心逻辑 ---

app = FastAPI(title="Simple MCP Provider")

# 用一个字典模拟多会话的上下文存储，生产环境应换成 Redis 或数据库
CONTEXT_STORE: Dict[str, Dict[str, ContextItem]] = {}

# 模拟的后端 LLM 调用
def mock_llm_call(prompt: str, context_str: str) -> str:
    print(f"\n--- Mock LLM Input ---")
    print(f"Context: {context_str}")
    print(f"Prompt: {prompt}")
    print(f"----------------------\n")
    return f"基于上下文 '{context_str}', 我对 '{prompt}' 的回答是：'这是一个模拟响应。'"

@app.post("/mcp")
async def handle_mcp_message(request: Request, message: MCPMessage):
    # 从 Header 获取会话 ID，如果没有则创建一个新的
    session_id = request.headers.get("X-Session-ID")
    if not session_id:
        session_id = str(uuid.uuid4())
        print(f"New session created: {session_id}")

    # 为新会话初始化上下文存储
    if session_id not in CONTEXT_STORE:
        CONTEXT_STORE[session_id] = {}

    session_context = CONTEXT_STORE[session_id]
    msg_type = message.message_type

    # --- 3. 根据消息类型进行分发处理 ---

    if msg_type == "context_update":
        payload = ContextUpdatePayload(**message.payload)
        if payload.add:
            for item in payload.add:
                session_context[item.item_id] = item
        if payload.update:
            for item in payload.update:
                session_context[item.item_id] = item
        if payload.remove:
            for item_id in payload.remove:
                session_context.pop(item_id, None)
        
        print(f"Context for session {session_id} updated. Current items: {list(session_context.keys())}")
        return {"status": "context updated", "session_id": session_id}

    elif msg_type == "model_request":
        payload = ModelRequestPayload(**message.payload)
        
        # 组装上下文
        relevant_context_str = ""
        if payload.context_item_ids:
            for item_id in payload.context_item_ids:
                if item_id in session_context:
                    relevant_context_str += str(session_context[item_id].content) + "\n"
                else:
                    raise HTTPException(status_code=400, detail=f"Context item {item_id} not found")

        # 调用（模拟的）LLM
        response_content = mock_llm_call(payload.prompt, relevant_context_str.strip())

        # 构建响应
        return {
            "protocol_version": "1.0",
            "message_id": f"resp-to-{message.message_id}",
            "message_type": "model_response",
            "payload": {
                "content": response_content,
                "usage": {"prompt_tokens": 50, "completion_tokens": 30}, # 模拟值
                "finish_reason": "stop"
            }
        }

    else:
        raise HTTPException(status_code=400, detail=f"Unsupported message type: {msg_type}")

if __name__ == "__main__":
    print("Starting MCP Provider on http://127.0.0.1:8000")
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

**如何运行服务端:**
1.  保存以上代码为 `mcp_provider.py`。
2.  在终端运行: `python mcp_provider.py`。

### 3. 客户端实现 (Client)

现在我们来编写一个客户端，与上面的服务端进行交互。

**文件: `mcp_client.py`**

```python
import httpx
import uuid

class MCPClient:
    def __init__(self, provider_url: str):
        self.provider_url = provider_url
        self.session_id = str(uuid.uuid4())
        self.client = httpx.Client(headers={
            "Content-Type": "application/json",
            "X-Session-ID": self.session_id
        })
        print(f"Client started with session ID: {self.session_id}")

    def _send_message(self, message_type: str, payload: dict) -> dict:
        message = {
            "protocol_version": "1.0",
            "message_id": str(uuid.uuid4()),
            "message_type": message_type,
            "payload": payload
        }
        try:
            response = self.client.post(self.provider_url, json=message)
            response.raise_for_status() # 如果是 4xx 或 5xx 错误，则抛出异常
            return response.json()
        except httpx.HTTPStatusError as e:
            print(f"Error response {e.response.status_code} while sending message: {e.response.text}")
            raise
        except httpx.RequestError as e:
            print(f"An error occurred while requesting {e.request.url!r}.")
            raise

    def update_context(self, add: list = None, remove: list = None):
        """
        更新上下文
        :param add: list of dicts, e.g., [{"item_id": "doc1", "content_type": "text/plain", "content": "..."}]
        :param remove: list of strings, e.g., ["doc2"]
        """
        payload = {}
        if add:
            payload["add"] = add
        if remove:
            payload["remove"] = remove
        
        print(f"\nSending context_update: adding {len(add or [])} items, removing {len(remove or [])} items.")
        return self._send_message("context_update", payload)

    def request_model(self, prompt: str, context_ids: list = None):
        """
        请求模型推理
        :param prompt: The user's prompt.
        :param context_ids: List of item_ids to use for this request.
        """
        payload = {
            "prompt": prompt,
            "context_item_ids": context_ids or []
        }
        print(f"\nSending model_request with prompt: '{prompt}'")
        response = self._send_message("model_request", payload)
        return response.get("payload", {}).get("content")

# --- 4. 客户端使用示例 ---

if __name__ == "__main__":
    # 确保你的 Provider 正在运行!
    provider_url = "http://127.0.0.1:8000/mcp"
    client = MCPClient(provider_url)

    # 步骤 1: 更新上下文，添加一个文档
    client.update_context(
        add=[
            {
                "item_id": "doc-annual-report",
                "content_type": "text/plain",
                "content": "公司2025年营收强劲增长。"
            }
        ]
    )

    # 步骤 2: 基于上下文进行提问
    response_content = client.request_model(
        prompt="总结一下公司的表现",
        context_ids=["doc-annual-report"]
    )
    print(f"Model Response: {response_content}")

    # 步骤 3: 进行无上下文的提问
    response_content_2 = client.request_model(
        prompt="你好吗？"
    )
    print(f"Model Response (no context): {response_content_2}")
```

**如何运行客户端:**
1.  确保服务端已在另一个终端运行。
2.  保存以上代码为 `mcp_client.py`。
3.  在终端运行: `python mcp_client.py`。
4.  观察客户端和服务端两个终端的输出，理解它们的交互流程。

### 4. 开发实践与高级技巧

#### 4.1. 客户端实践

*   **管理复杂上下文**: 在实际应用中，`content` 可以来自文件、数据库等。
    ```python
    # 从文件加载上下文
    with open("my_document.txt", "r") as f:
        doc_content = f.read()
    
    client.update_context(add=[
        {
            "item_id": "file-doc",
            "content_type": "text/plain",
            "content": doc_content
        }
    ])
    ```
*   **上下文策略**: 对于长对话，客户端需要决定何时丢弃旧的上下文以避免超出窗口限制。
    *   **滑动窗口**: 只保留最近的 N 轮对话。可以在客户端维护一个对话列表，当列表超长时，通过 `remove` 参数在 `context_update` 中移除最旧的消息 `item_id`。
    *   **摘要**: 更高级的策略是，当上下文过长时，客户端可以先调用一次模型对自己管理的上下文进行摘要，然后用摘要替换掉原始的长上下文。
*   **错误处理与重试**: 上面的客户端代码中已包含基础的 `try...except`。在生产环境中，可以引入 `tenacity` 等库来实现更健壮的指数退避重试逻辑。

#### 4.2. 服务端实践

*   **上下文存储 (Context Storage)**:
    *   **内存存储 (如示例)**: 优点是快，缺点是服务重启后数据丢失，且无法在多个服务实例间共享。只适用于测试和单实例部署。
    *   **Redis**: 极佳的选择。使用 Redis Hashes，可以用 `session_id` 作为 Key，`item_id` 作为 Field，实现快速的上下文读写和持久化。
    *   **向量数据库 (Vector DB)**: 最高级的方案。当 `context_update` 时，服务端不仅存储原始内容，还将其**向量化**。当 `model_request` 进来时，服务端可以先将 `prompt` 向量化，然后进行相似度搜索，**自动**找出最相关的上下文条目，即使客户端没有在 `context_item_ids` 中明确指定。这极大地增强了模型的知识检索能力。

*   **多租户与上下文隔离**:
    *   我们示例中的 `X-Session-ID` Header 和 `CONTEXT_STORE` 字典就是最基础的多租户隔离实现。每个用户的请求都通过其唯一的 `session_id` 被路由到其专属的上下文“沙箱”中，确保数据不会串流。

*   **集成真实后端模型**:
    *   在服务端的 `mock_llm_call` 函数中，替换成对 OpenAI, Anthropic, 或其他本地模型的真实 API 调用。你需要将从 `CONTEXT_STORE` 中检索到的上下文内容格式化成符合目标模型 API 要求的格式（例如，OpenAI 的 `messages` 数组）。

*   **性能与可伸缩性**:
    *   `fastapi` 的异步特性是高并发的基础。
    *   对于计算密集的模型推理，可以将其放到一个独立的任务队列中（如 Celery），避免阻塞主服务线程。
    *   使用 Redis 等外部存储是实现多实例水平扩展的前提。
