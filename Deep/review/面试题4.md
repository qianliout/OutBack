根据这份针对“智能化办公 Agent”与“AI 搜索问答”的招聘需求，该岗位核心聚焦于多 Agent 架构设计、RAG（检索增强生成）系统优化以及实际办公场景的落地能力。

以下为您设计的面试题，旨在考察候选人在架构设计、算法原理、工程落地及场景优化方面的综合能力。

📝 第三部分：会议 AI 与生成质量

长文本摘要与待办提取
题目：
“针对长达 2 小时的会议录音转写文本，直接使用大模型进行摘要往往会超出上下文窗口或导致关键信息遗漏。请设计一套处理长文本的方案（如 Map-Reduce, Refine 等），并重点说明如何从杂乱的对话中精准提取‘待办事项（Action Items）’，确保提取出的任务包含明确的‘责任人’和‘截止时间’。”

考察点：
长文本处理能力与上下文窗口管理策略。
信息抽取（Information Extraction）的 Prompt 设计与结构化输出能力。
对业务目标（明确责任人和时间）的工程化实现手段。

提示词工程的高级应用
题目：
“请分享一个你过往使用 Chain of Thought (CoT) 解决复杂逻辑推理问题的实际案例。在办公场景中，如果用户提问‘我想请假，但我不知道这周有没有重要会议’，Agent 需要先查询日历，再判断会议重要性，最后决定是否建议请假。你会如何设计 Prompt 引导模型进行这种多步推理，并避免模型在中间步骤产生幻觉？”

考察点：
CoT 的实际编写与调试技巧。
逻辑推理链的设计与幻觉抑制方法。
将业务逻辑转化为模型推理步骤的能力。

🛠️ 第四部分：工程基础与综合实战

系统性能与并发处理
题目：
“假设我们的智能办公助手需要支持全公司 5000 人同时在线使用，且对响应延迟有严格要求（如搜索需在 1 秒内返回）。考虑到 LLM 推理和向量检索的高耗时，你会从系统架构层面采取哪些优化措施（如缓存策略、异步处理、流式输出等）？在 Python 或 Go 语言环境下，如何高效管理大并发请求？”

考察点：
高并发系统架构设计能力。
对 LLM 应用性能瓶颈的识别与优化手段（缓存、异步、批处理）。
编程语言（Python/Go）在工程落地中的具体应用。

评估体系建设
题目：
“在优化‘会议纪要总结’或‘AI 搜索’效果时，不能仅靠体感。请设计一套自动化的评估体系，包含哪些核心指标（如召回率、准确率、Faithfulness 等）？你会如何构建测试数据集，并利用大模型（LLM-as-a-Judge）来辅助评估生成内容的质量？”

考察点：
对 RAGAS 或类似评估框架的了解。
定量评估与定性评估相结合的方法论。
构建自动化测试与持续集成（CI/CD）流程的意识。

数学基础与算法原理
题目：
“在向量检索中，余弦相似度和欧几里得距离是两种常见的度量方式。请从数学角度解释它们的区别，并说明在处理高维文本向量时，为什么通常首选余弦相似度？此外，当数据量达到亿级时，你会选择哪种近似最近邻搜索（ANNS）算法（如 HNSW, IVF）？为什么？”

考察点：
扎实的数学基础（线性代数、几何距离）。
对向量数据库底层索引原理（如 HNSW 图算法）的理解。
理论与工程实践的结合能力。

场景故障排查
题目：
“上线后收到反馈，Agent 在处理‘请假’任务时，偶尔会错误地将‘下周三’识别为‘本周三’，导致日程预订错误。除了修改 Prompt 让模型‘更小心’之外，请从系统设计的角度提出一套完整的解决方案，包括时间实体的标准化处理、外部工具辅助校验以及用户确认机制的设计。”

考察点：
解决实际业务痛点（时间实体识别）的综合能力。
防御性编程与“人机回环”（Human-in-the-loop）设计。
对大模型不可靠性的工程补偿策略。
