## 一、Go 并发编程基础

### 1.1 Go 并发哲学

Go 的并发哲学源自 **CSP（Communicating Sequential Processes，通信顺序进程）** 模型，核心思想是：

> "**不要通过共享内存来通信；相反，通过通信来共享内存。**"

**传统方式（共享内存）：**
```
Goroutine A ──→ 写入共享内存 ──→ Goroutine B 读取
                     ↓
              需要加锁保护
```

**Go 方式（通信）：**
```
Goroutine A ──→ Channel 发送 ──→ Goroutine B 接收
                     ↓
              数据所有权转移
```

这种设计使得并发代码更易于理解和维护，因为数据的流动方向就是代码的执行顺序。

---

### 1.2 Goroutine 详解

Goroutine 是 Go 运行时管理的轻量级线程，由 `go` 关键字启动。

**创建 Goroutine：**

```go
func main() {
    go say("Hello")      // 启动一个 goroutine
    go func() {
        println("Inline")
    }()
}
```

**Goroutine 的生命周期：**

1. **创建**：通过 `go` 关键字创建
2. **执行**：由 Go 运行时调度执行
3. **退出**：主函数返回或主动 `return`

**重要特性：**

| 特性 | 说明 |
|:--|:--|
| **轻量级** | 初始栈大小仅 2KB，可动态增长 |
| **由 Go 调度** | 不是系统线程，由 GMP 模型调度 |
| **非阻塞** | 阻塞 I/O 时调度器会自动切换 |
| **无主从关系** | 所有 goroutine 平等，都可能被回收 |

**注意事项：**

```go
func main() {
    go println("这里不会打印")

    // 主函数太快结束，goroutine 来不及执行
}
```

上面代码可能什么都打印不出来，因为主 goroutine 退出时不会等待其他 goroutine。

## 二、协程间通信

### 2.1 Channel 语法与分类

Channel 是 Go 提供的**类型安全的通信管道**，用于在 goroutine 之间传递数据。

**创建 Channel：**

```go
// 无缓冲 channel
ch1 := make(chan int)

// 有缓冲 channel
ch2 := make(chan int, 5)
```

**Channel 分类对比：**

| 特性 | 无缓冲 Channel | 有缓冲 Channel |
|:--|:--|:--|
| **缓冲大小** | 0 | 指定大小 |
| **发送阻塞** | 等待接收者 | 缓冲满时阻塞 |
| **接收阻塞** | 等待发送者 | 缓冲空时阻塞 |
| **同步性** | 强同步（ Rendezvous） | 弱同步 |

**工作原理图解：**

```
无缓冲 Channel:
  Goroutine A ──send──→ [Channel] ──receive──→ Goroutine B
  （必须同时准备好才能完成）

有缓冲 Channel (cap=3):
  Goroutine A ──send──→ [□ □ □] ──receive──→ Goroutine B
       │                      │                    ↑
       └──────────────────────┘                    │
                   缓冲队列                    消费后弹出
```

---

### 2.2 Channel 操作规则

**发送与接收：**

```go
ch := make(chan int, 3)

// 发送
ch <- 1
ch <- 2

// 接收
v := <-ch
fmt.Println(v) // 1
```

**关闭 Channel：**

```go
ch := make(chan int)

// 生产者关闭
close(ch)

// 消费者检测关闭
v, ok := <-ch
if !ok {
    println("Channel 已关闭")
}

// 或使用 range
for v := range ch {
    println(v)
}
```

**关闭规则：**

| 操作 | 说明 |
|:--|:--|
| `close(nil)` | panic |
| `close(<-chan)` | panic（只能关闭发送方向的 channel） |
| `send to closed` | panic |
| `receive from closed` | 返回零值和不安全标志 |

**单向 Channel：**

```go
// 生产者只能发送
func producer(ch chan<- int) {
    ch <- 1
    close(ch)
}

// 消费者只能接收
func consumer(ch <-chan int) {
    for v := range ch {
        fmt.Println(v)
    }
}
```

### 2.3 select 多路复用

`select` 允许同时监听多个 channel 的读写操作，类似于 `switch` 但用于 channel。

**基本语法：**

```go
select {
case v := <-ch1:
    fmt.Println("收到 ch1:", v)
case v := <-ch2:
    fmt.Println("收到 ch2:", v)
case ch3 <- 1:
    fmt.Println("发送到 ch3")
default:
    fmt.Println("所有 case 都阻塞，执行 default")
}
```

**特性：**

1. **随机选择**：多个 case 同时就绪时，随机选择一个执行
2. **阻塞等待**：没有 default 时，select 会阻塞直到某个 case 就绪
3. **超时处理**：常配合 `time.After` 实现超时

**超时机制：**

```go
select {
case v := <-ch:
    fmt.Println("收到:", v)
case <-time.After(time.Second):
    fmt.Println("超时")
}
```

**关闭监听：**

```go
for {
    select {
    case v, ok := <-ch:
        if !ok {
            return // channel 关闭，退出
        }
        fmt.Println("处理:", v)
    }
}
```

### 2.4 Pipeline 模式

Pipeline（管道）是一种将多个处理阶段串联起来的设计模式，每个阶段由一组 goroutine 组成，通过 channel 连接。

**核心概念：**

```
Stage 1          Stage 2          Stage 3
[生成数据] ──→ [处理数据] ──→ [输出结果]
    ↓              ↓               ↓
 Channel 1      Channel 2       Channel 3
```

**经典 Pipeline 示例：**

```go
package main

import "fmt"

func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        for _, n := range nums {
            out <- n
        }
        close(out)
    }()
    return out
}

func square(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        for n := range in {
            out <- n * n
        }
        close(out)
    }()
    return out
}

func main() {
    // Pipeline: generate → square → 输出
    for n := range square(square(generate(1, 2, 3, 4, 5))) {
        fmt.Println(n) // 1, 16, 81, 256, 625
    }
}
```

**Pipeline 最佳实践：**

```go
// 1. 将 stages 作为函数返回 receive-only channel
// 2. 每个 stage 都要负责关闭自己的输出 channel
// 3. 每个 stage 要持续从输入读取直到 channel 关闭

func pipelineStage(in <-chan int) (<-chan int, <-chan error) {
    out := make(chan int)
    errc := make(chan error, 1)

    go func() {
        defer close(out)
        defer close(errc)

        for n := range in {
            // 处理逻辑
            result, err := process(n)
            if err != nil {
                errc <- err
                return
            }
            out <- result
        }
    }()

    return out, errc
}
```

**Pipeline 的错误处理：**

```go
func merge(cs ...<-chan int) <-chan int {
    var wg sync.WaitGroup
    out := make(chan int)

    output := func(c <-chan int) {
        for n := range c {
            out <- n
        }
        wg.Done()
    }

    wg.Add(len(cs))
    for _, c := range cs {
        go output(c)
    }

    go func() {
        wg.Wait()
        close(out)
    }()

    return out
}
```

## 三、同步原语

### 3.1 WaitGroup

`WaitGroup` 用于等待一组 goroutine 执行完毕。

**核心方法：**

| 方法 | 说明 |
|:--|:--|
| `Add(delta int)` | 增加需要等待的 goroutine 数量 |
| `Done()` | 一个 goroutine 完成，计数减 1 |
| `Wait()` | 阻塞直到计数归零 |

**正确用法：**

```go
func main() {
    var wg sync.WaitGroup

    for i := 0; i < 10; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done() // 关键：确保一定会执行
            doWork(id)
        }(i)
    }

    wg.Wait() // 等待所有 goroutine 完成
    fmt.Println("全部完成")
}
```

**常见错误：**

```go
// ❌ 错误：将 Add 放在循环外面
var wg sync.WaitGroup
for i := 0; i < 10; i++ {
    wg.Add(1) // 每次循环都加 1，OK
    go func() {
        defer wg.Done()
    }()
}

// ❌ 错误：在 goroutine 内部调用 Add
go func() {
    wg.Add(1) // 不要这样！Add 应该在启动 goroutine 之前
}()
```

**原理简析：**

- 内部有一个计数器（counter）和一个信号量（semaphore）
- `Add` 修改计数器，`Done` 调用 `Add(-1)`
- `Wait` 实际是通过信号量阻塞当前 goroutine

### 3.2 Mutex 与 RWMutex

**sync.Mutex（互斥锁）：**

```go
var (
    counter int
    mu      sync.Mutex
)

func increment() {
    mu.Lock()
    defer mu.Unlock()
    counter++ // 临界区
}
```

**sync.RWMutex（读写锁）：**

适用于读多写少场景：
- **RLock/RUnlock**：多个 goroutine 可以同时持有读锁
- **Lock/Unlock**：写操作独占锁

```go
var (
    data   map[string]string
    mu     sync.RWMutex
)

func Read(key string) string {
    mu.RLock()
    defer mu.RUnlock()
    return data[key]
}

func Write(key, value string) {
    mu.Lock()
    defer mu.Unlock()
    data[key] = value
}
```

**锁选择原则：**

| 场景 | 推荐 |
|:--|:--|
| 读远多于写 | RWMutex |
| 读写差不多 | RWMutex 或 Mutex |
| 写操作复杂 | Mutex |
| 只做简单计数 | atomic |

**死锁风险：**

```go
// ❌ 错误：不可重入，同一 goroutine 不能重复加锁
mu.Lock()
mu.Lock() // 这里会永久阻塞！

// ✅ 正确：defer 解锁
mu.Lock()
defer mu.Unlock()
```

**锁的底层原理（简化）：**

Go 的 Mutex 基于 **CAS（Compare-And-Swap）** 操作和操作系统提供的信号量实现：
1. 首先尝试使用 CAS 快速获取锁（自旋）
2. 自旋失败后，挂起 goroutine 到信号量上
3. 解锁时，优先唤醒等待的 goroutine

---

### 3.3 原子操作 atomic

`atomic` 包提供底层的原子操作，用于无锁同步，性能优于锁。

**支持的类型：**

| 函数 | 说明 |
|:--|:--|
| `atomic.AddInt64(&v, delta)` | 原子加减 |
| `atomic.LoadInt64(&v)` | 原子读取 |
| `atomic.StoreInt64(&v, val)` | 原子写入 |
| `atomic.SwapInt64(&v, new)` | 原子交换 |
| `atomic.CompareAndSwapInt64(&v, old, new)` | CAS 操作 |

**示例：计数器：**

```go
var counter int64

func increment() {
    atomic.AddInt64(&counter, 1)
}

func getCounter() int64 {
    return atomic.LoadInt64(&counter)
}
```

**标志位操作：**

```go
var flag int64

func setFlag() {
    atomic.StoreInt64(&flag, 1)
}

func isFlagSet() bool {
    return atomic.LoadInt64(&flag) == 1
}
```

**CAS 模式：**

```go
var value int64

// 乐观锁模式
func compareAndSwap(old, new int64) bool {
    return atomic.CompareAndSwapInt64(&value, old, new)
}

// 使用 CAS 实现复杂操作
func addIfPositive(delta int64) bool {
    for {
        old := atomic.LoadInt64(&value)
        if old <= 0 {
            return false
        }
        if atomic.CompareAndSwapInt64(&value, old, old+delta) {
            return true
        }
    }
}
```

**atomic 与 Mutex 对比：**

| 方面 | atomic | Mutex |
|:--|:--|:--|
| 适用场景 | 单个变量 | 复杂数据结构 |
| 性能 | 更高（CPU 指令级） | 较低（内核态切换） |
| 功能 | 有限 | 强大 |
| 死锁风险 | 无 | 可能 |

### 3.4 其他同步工具

**sync.Once（只执行一次）：**

```go
var (
    once     sync.Once
    resource *Resource
)

func GetResource() *Resource {
    once.Do(func() {
        resource = &Resource{}
    })
    return resource
}
```

**sync.Cond（条件变量）：**

用于 goroutine 等待某个条件满足：

```go
cond := sync.NewCond(&sync.Mutex{})

go func() {
    cond.L.Lock()
    for !condition {
        cond.Wait() // 等待时会释放锁
    }
    // 条件满足，处理
    cond.L.Unlock()
}()

// 另一个 goroutine 通知
cond.Signal() // 唤醒一个
cond.Broadcast() // 唤醒所有
```

**sync.Pool（对象池）：**

用于缓存临时对象，减少 GC 压力：

```go
var pool = sync.Pool{
    New: func() interface{} {
        return &bytes.Buffer{}
    },
}

func getBuffer() *bytes.Buffer {
    return pool.Get().(*bytes.Buffer)
}

func putBuffer(buf *bytes.Buffer) {
    buf.Reset()
    pool.Put(buf)
}
```

**sync.Map（并发安全 Map）：**

专为两种场景优化：
1. 键只写入一次，之后大量读取
2. 多个 goroutine 操作互不相交的键集合

```go
var m sync.Map

// 存储
m.Store("key", "value")

// 读取
if v, ok := m.Load("key"); ok {
    fmt.Println(v)
}

// 遍历
m.Range(func(k, v interface{}) bool {
    fmt.Printf("%s: %s\n", k, v)
    return true
})

// 删除
m.Delete("key")
```

## 四、并发安全数据结构

### 4.1 sync.Map

`sync.Map` 是专为并发访问设计的 Map，但并非所有场景都优于 `map + Mutex`。

**性能对比：**

| 操作 | sync.Map | map + Mutex |
|:--|:--|:--|
| 读单一键 | 快 | 需要加锁 |
| 写单一键 | 较快 | 需要加锁 |
| 遍历 | 需要 Range | 需要加锁 |
| 大量读写同一键 | 较慢 | 需要加锁 |

**使用场景：**

```go
// ✅ 适合：读多写少的配置缓存
var config sync.Map

func loadConfig() {
    config.Store("timeout", 30)
    config.Store("retry", 3)
}

func getConfig(key string) interface{} {
    v, _ := config.Load(key)
    return v
}

// ✅ 适合：键集合互不相交的并发写入
var idMap sync.Map

func processBatch(id int, items []string) {
    for _, item := range items {
        idMap.Store(item, id)
    }
}
```

**❌ 不适合：需要同时读写大量相同键**

```go
// 这种场景应该用 map + Mutex
var (
    mu   sync.Mutex
    data = make(map[string]int)
)

func update(key string, delta int) {
    mu.Lock()
    data[key] += delta
    mu.Unlock()
}
```

### 4.2 并发安全队列

**基于 Channel 的队列：**

```go
type Queue struct {
    ch chan int
}

func NewQueue(cap int) *Queue {
    return &Queue{ch: make(chan int, cap)}
}

func (q *Queue) Push(v int) bool {
    select {
    case q.ch <- v:
        return true
    default:
        return false // 队列满
    }
}

func (q *Queue) Pop() (int, bool) {
    select {
    case v := <-q.ch:
        return v, true
    default:
        return 0, false // 队列空
    }
}
```

**基于 Mutex + Slice 的队列：**

```go
type SafeSlice struct {
    mu    sync.Mutex
    items []int
}

func (s *SafeSlice) Push(v int) {
    s.mu.Lock()
    s.items = append(s.items, v)
    s.mu.Unlock()
}

func (s *SafeSlice) Pop() (int, bool) {
    s.mu.Lock()
    defer s.mu.Unlock()
    if len(s.items) == 0 {
        return 0, false
    }
    v := s.items[0]
    s.items = s.items[1:]
    return v, true
}
```

## 五、经典并发模式

### 5.1 生产者-消费者

**模式图解：**

```
Producer 1 ──┐
Producer 2 ──┼──→ [Channel] ──→ Consumer 1
Producer 3 ──┘                         ↓
                                   [处理结果]
```

**单生产者单消费者：**

```go
func main() {
    ch := make(chan int, 100)

    // 生产者
    go producer(ch, 1, 2, 3, 4, 5)

    // 消费者
    consumer(ch)
}

func producer(ch chan<- int, nums ...int) {
    for _, n := range nums {
        ch <- n
    }
    close(ch)
}

func consumer(ch <-chan int) {
    for n := range ch {
        fmt.Println("消费:", n)
    }
}
```

**多生产者多消费者：**

```go
func main() {
    ch := make(chan int, 100)

    var wg sync.WaitGroup

    // 3 个生产者
    for i := 0; i < 3; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            for j := 0; j < 5; j++ {
                ch <- id*10 + j
            }
        }(i)
    }

    // 2 个消费者
    for c := 0; c < 2; c++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            for n := range ch {
                fmt.Printf("Consumer %d: %d\n", id, n)
            }
        }(c)
    }

    wg.Wait()
}
```

### 5.2 工作池模式

**模式图解：**

```
        ┌─────────────────────────────────┐
        │         Task Queue (Channel)    │
        │   task1, task2, task3, ...      │
        └─────────────────────────────────┘
              ↑           ↑           ↑
         Worker 1     Worker 2     Worker N
              │           │           │
              └───────────┴───────────┘
                        ↓
                   Results (Channel)
```

**标准工作池实现：**

```go
type Job struct {
    ID   int
    Data string
}

type Result struct {
    JobID  int
    Output string
}

func workerPool(numWorkers int, jobs <-chan Job, results chan<- Result) {
    var wg sync.WaitGroup

    for i := 0; i < numWorkers; i++ {
        wg.Add(1)
        go func(workerID int) {
            defer wg.Done()
            for job := range jobs {
                // 模拟处理
                output := process(job)
                results <- Result{
                    JobID:  job.ID,
                    Output: output,
                }
            }
        }(i)
    }

    wg.Wait()
    close(results)
}

func process(job Job) string {
    time.Sleep(100 * time.Millisecond) // 模拟工作
    return fmt.Sprintf("处理结果: %s", job.Data)
}

func main() {
    jobs := make(chan Job, 100)
    results := make(chan Result, 100)

    // 启动工作池（4 个 worker）
    go workerPool(4, jobs, results)

    // 发送任务
    go func() {
        for i := 0; i < 20; i++ {
            jobs <- Job{ID: i, Data: fmt.Sprintf("task-%d", i)}
        }
        close(jobs)
    }()

    // 收集结果
    for r := range results {
        fmt.Printf("Job %d 完成: %s\n", r.JobID, r.Output)
    }
}
```

**带错误处理的工作池：**

```go
func workerPoolWithErrors(numWorkers int, jobs <-chan Job) <-chan error {
    errCh := make(chan error, numWorkers)
    done := make(chan struct{})

    for i := 0; i < numWorkers; i++ {
        go func() {
            for job := range jobs {
                if err := processWithError(job); err != nil {
                    select {
                    case errCh <- err:
                    case <-done:
                    }
                }
            }
        }()
    }

    go func() {
        var wg sync.WaitGroup
        for range jobs {
            wg.Wait()
        }
        close(errCh)
    }()

    return errCh
}
```

### 5.3 扇入扇出

**扇出（Fan-out）：** 一个任务分发给多个 worker 并行处理

**扇入（Fan-in）：** 多个来源的结果合并到一个 channel

**模式图解：**

```
        ┌── Worker 1
        │
Source ─┼── Worker 2 ──→ Merge ──→ Output
        │
        └── Worker 3
    (Fan-out)              (Fan-in)
```

**完整示例：**

```go
func main() {
    // 1. 数据源
    source := generate(1, 2, 3, 4, 5, 6, 7, 8)

    // 2. 扇出：启动多个 worker
    numWorkers := 3
    channels := make([]<-chan int, numWorkers)

    for i := 0; i < numWorkers; i++ {
        channels[i] = worker(source, i)
    }

    // 3. 扇入：合并结果
    merged := merge(channels...)

    // 4. 输出
    for v := range merged {
        fmt.Println("结果:", v)
    }
}

func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        for _, n := range nums {
            out <- n
        }
        close(out)
    }()
    return out
}

func worker(in <-chan int, workerID int) <-chan int {
    out := make(chan int)
    go func() {
        for v := range in {
            // 模拟处理
            time.Sleep(50 * time.Millisecond)
            out <- v * v
        }
        close(out)
    }()
    return out
}

func merge(channels ...<-chan int) <-chan int {
    var wg sync.WaitGroup
    out := make(chan int)

    output := func(c <-chan int) {
        for v := range c {
            out <- v
        }
        wg.Done()
    }

    wg.Add(len(channels))
    for _, c := range channels {
        go output(c)
    }

    go func() {
        wg.Wait()
        close(out)
    }()

    return out
}
```

**应用场景：**

- **并行计算**：将大数据集分成多份，并行处理后合并
- **多源获取**：同时从多个 API 获取数据
- **负载均衡**：将任务均匀分配给多个 worker

### 5.4 errgroup 并发模式

`golang.org/x/sync/errgroup` 是 Go 官方提供的并发错误处理库，非常适合处理"一组任务并行执行，任意一个失败则整体失败"的场景。

**核心接口：**

```go
type Group struct {
    Cancel func()
}

func (g *Group) Go(fn func() error)
func (g *Group) Wait() error
```

**基本用法：**

```go
import "golang.org/x/sync/errgroup"

func fetchAll(urls []string) ([]string, error) {
    g := new(errgroup.Group)
    results := make([]string, len(urls))

    for i, url := range urls {
        i, url := i, url // 创建新变量避免闭包问题
        g.Go(func() error {
            resp, err := http.Get(url)
            if err != nil {
                return err
            }
            defer resp.Body.Close()

            body, err := io.ReadAll(resp.Body)
            if err != nil {
                return err
            }
            results[i] = string(body)
            return nil
        })
    }

    if err := g.Wait(); err != nil {
        return nil, err
    }
    return results, nil
}
```

**带 Context 的用法：**

```go
func fetchWithContext(ctx context.Context, urls []string) ([]string, error) {
    g, ctx := errgroup.WithContext(ctx)
    results := make([]string, len(urls))

    for i, url := range urls {
        i, url := i, url
        g.Go(func() error {
            req, err := http.NewRequestWithContext(ctx, "GET", url, nil)
            if err != nil {
                return err
            }

            resp, err := http.DefaultClient.Do(req)
            if err != nil {
                return err
            }
            defer resp.Body.Close()

            body, err := io.ReadAll(resp.Body)
            if err != nil {
                return err
            }
            results[i] = string(body)
            return nil
        })
    }

    if err := g.Wait(); err != nil {
        return nil, err
    }
    return results, nil
}
```

**关键特性：**

1. **第一个错误优先**：当某个 goroutine 返回错误时，会取消其他 goroutine
2. **Context 集成**：可以自动传播取消信号
3. **阻塞 Wait**：`Wait()` 会等待所有 goroutine 完成后才返回

**原理简析：**

```go
func (g *Group) Go(fn func() error) {
    atomic.AddInt32(&g.n, 1)
    go func() {
        defer func() {
            if atomic.AddInt32(&g.n, -1) == 0 {
                release(g.done)
            }
        }()

        if err := fn(); err != nil {
            // 第一个错误会取消整个 group
            atomic.CompareAndSwapInt32(&g.err, 0, 1)
            cancel()
        }
    }()
}
```

**典型应用场景：**

```go
// 1. 并行下载文件
g, ctx := errgroup.WithContext(context.Background())
for i, url := range urls {
    i, url := i, url
    g.Go(func() error {
        return downloadFile(ctx, url, filenames[i])
    })
}
if err := g.Wait(); err != nil {
    log.Fatal(err)
}

// 2. 并行数据库查询
g, ctx := errgroup.WithContext(ctx)
for _, query := range queries {
    query := query
    g.Go(func() error {
        return executeQuery(ctx, query)
    })
}
if err := g.Wait(); err != nil {
    log.Fatal(err)
}

// 3. 服务启动时的健康检查
g, ctx := errgroup.WithContext(ctx)
g.Go(func() error { return checkRedis(ctx) })
g.Go(func() error { return checkMySQL(ctx) })
g.Go(func() error { return checkKafka(ctx) })
if err := g.Wait(); err != nil {
    log.Fatal("服务启动失败:", err)
}
```

### 7.3 常见并发 Bug

**1. 忘记解锁：**

```go
// ❌ 错误
mu.Lock()
if condition {
    return // 死锁！
}
mu.Unlock()

// ✅ 正确：使用 defer
mu.Lock()
defer mu.Unlock()
```

**2. 死锁（循环等待）：**

```go
// ❌ 错误：不同的加锁顺序
go func() {
    muA.Lock()
    muB.Lock() // 可能死锁
}()
go func() {
    muB.Lock()
    muA.Lock() // 可能死锁
}()

// ✅ 正确：统一的加锁顺序
go func() {
    muA.Lock()
    muB.Lock()
    muA.Unlock()
    muB.Unlock()
}()
```

**3. Channel 未关闭导致泄漏：**

```go
// ❌ 错误
go func() {
    for i := 0; i < 10; i++ {
        ch <- i
    }
    //忘记 close(ch)
}()

// ✅ 正确：defer close
go func() {
    defer close(ch)
    for i := 0; i < 10; i++ {
        ch <- i
    }
}()
```

**4. 往已关闭的 Channel 发送数据：**

```go
// ❌ 错误
close(ch)
ch <- 1 // panic: send on closed channel

// ✅ 正确：使用 ok 检查
ch <- 1
close(ch)
```

**5. 闭包变量捕获问题：**

```go
// ❌ 错误
for i := 0; i < 5; i++ {
    go func() {
        fmt.Println(i) // 全部打印 5
    }()
}

// ✅ 正确：传递变量
for i := 0; i < 5; i++ {
    go func(id int) {
        fmt.Println(id)
    }(i)
}
```

## 八、最佳实践

### 8.1 工具选择指南

```
问题：需要保护什么？
│
├─ 只需要传递数据所有权 ──→ Channel
│
├─ 需要等待一组任务完成 ──→ WaitGroup / errgroup
│
├─ 需要保护简单变量 ──→ atomic（计数）或 mutex（复杂）
│
├─ 需要并发读写 Map ──→ sync.Map（特定场景）或 map + RWMutex
│
└─ 需要协调多个 goroutine ──→ sync.Cond
```

### 8.2 项目中的标准写法

**1. 使用 errgroup 处理并发错误：**

```go
g, ctx := errgroup.WithContext(context.Background())
for _, task := range tasks {
    task := task
    g.Go(func() error {
        return processTask(ctx, task)
    })
}
return g.Wait()
```

**2. 使用带超时的 Context：**

```go
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

if err := doSomething(ctx); err != nil {
    // 超时或取消
}
```

**3. 使用 defer 确保清理：**

```go
mu.Lock()
defer mu.Unlock()
// 处理共享资源
```

**4. 优先使用 Channel 而非共享内存：**

```go
// ✅ 好的设计
result := processInGoroutine(input)
return <-result

// ❌ 次优设计
var result int
var mu sync.Mutex
go func() {
    mu.Lock()
    result = process(input)
    mu.Unlock()
}()
```

### 8.3 性能注意事项

| 场景 | 建议 |
|:--|:--|
| 高频锁竞争 | 使用 atomic 或细分锁粒度 |
| 大量 goroutine | 使用工作池限制数量 |
| Channel 传递大数据 | 传递指针而非拷贝 |
| sync.Map | 仅在适合的场景使用 |

### 8.4 总结

| 工具 | 适用场景 |
|:--|:--|
| **Channel** | 任务分发、数据流处理、所有权传递 |
| **WaitGroup** | 等待一组任务完成 |
| **Mutex/RWMutex** | 保护共享状态 |
| **atomic** | 简单计数、标志位 |
| **sync.Map** | 读多写少或键不重叠 |
| **sync.Once** | 单次初始化 |
| **sync.Pool** | 对象复用，减少 GC |
| **sync.Cond** | 条件等待 |
| **errgroup** | 并发任务 + 错误传播 |
| **Context** | 取消信号、超时、请求值传递 |

---

> Go 的并发哲学是"通过通信来共享内存"，Channel 是核心。优先使用 Channel 设计并发程序，当性能或场景不满足时再考虑 Mutex 等底层同步工具。

#### 1. 开场定调

Golang 的并发核心是 **CSP 模型**（Communicating Sequential Processes），主张"**通过通信来共享内存，而不是通过共享内存来通信**"。

相比传统语言的线程模型，Golang 用 **Goroutine** 替代了线程，由 Go 运行时（Runtime）自己调度，**一个 OS 线程可以承载成千上万个 Goroutine**，这使得并发编程变得非常轻量。

---

#### 2. 核心组成

**Goroutine（协程）：**

```go
go func() { ... }()
```

- 由 `go` 关键字启动，是用户态的轻量级线程
- 初始栈仅 2KB，可动态增长
- 不需要手动管理生命周期

**Channel（通道）：**

```go
ch := make(chan int, 10)
```

- Go 独有的类型，是 Goroutine 之间的通信管道
- 本身是并发安全的，无需加锁
- 支持 `select` 多路复用

**sync 包（同步原语）：**

| 工具 | 用途 |
|:--|:--|
| `sync.Mutex/RWMutex` | 互斥锁，保护共享状态 |
| `sync.WaitGroup` | 等待一组任务完成 |
| `sync.Once` | 只执行一次 |
| `sync.Cond` | 条件变量 |
| `sync.Map` | 并发安全 Map |
| `sync.Pool` | 对象池 |

---

#### 3. 底层原理：GMP 调度模型

这是面试加分项！

```
G (Goroutine) ──→  用户代码
     │
     ↓
P (Processor) ────→ Go Runtime 分配的逻辑处理器
     │
     ↓
M (Machine) ──────→ 操作系统线程

全局队列 (Global Queue)：存放等待运行的 G
P 的本地队列：每个 P 自己维护的 G 队列
```

**调度流程：**

1. G 创建后放入 P 的本地队列（或全局队列）
2. M 从 P 的本地队列取出 G 执行
3. 如果 P 的队列空了，尝试从全局队列或其他 P 的队列偷取一半
4. M 执行 G 时，如果发生阻塞（如系统调用），会分离出新的 M 来服务 P

**为什么快？**

- **Work-Stealing**：空闲的 P 会从其他 P 偷 G，减少浪费
- **自旋线程**：有 M 在等待 G 时，不会真的让 CPU 空转
- **抢占式调度**：某个 G 长时间运行，会被强制抢走

#### 4. 实际项目中的并发设计

**常见模式：**

```go
// 1. errgroup 并发处理 + 错误传播

    task := task

    workerPool <- struct{}{}
    go func(j Job) {
        defer func() { <-workerPool }()
        process(j)
    }(job)
}

// 3. Pipeline 数据流处理
source := generate(1, 2, 3, 4, 5)
filtered := filter(source, func(n int) bool { return n%2 == 0 })
result := process(filtered)
```

**如何选择工具？**

```
需要传递数据 → Channel
需要等待完成 → WaitGroup / errgroup
需要保护状态 → Mutex / RWMutex
简单计数     → atomic
读多写少     → sync.Map 或 RWMutex
并发安全单例 → sync.Once
```

#### 6. 总结升华

Go 的并发设计非常优雅：

1. **语言层面支持**：`go` 关键字让并发变成一等公民
2. **Runtime 接管调度**：不需要线程池、不需要手动管理
3. **Channel 传递数据**：避免了锁的复杂性，让数据流更清晰
4. **丰富的 sync 工具**：覆盖了各种同步场景

**我的理解：**

- 优先用 **Channel** 设计并发程序，符合 Go 的哲学
- 遇到**性能瓶颈**或**复杂状态保护**时，选择合适的 **sync 原语**
- 始终用 **-race** 检测并发问题，养成习惯
- 理解 **GMP 模型**有助于写出更高效的并发代码
