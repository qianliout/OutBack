Python 协程与 Go goroutine 虽然都叫"协程"，但在实现、调度、执行模型、与线程的关系上存在根本差异。

---

## 一、实现

| 维度    | Python (async/await)                                   | Go (goroutine)                                    |
| ----- | ------------------------------------------------------ | ------------------------------------------------- |
| 本质    | 无栈协程（stackless），由生成器 + `yield from` 驱动                 | 有栈协程（stackful），每个 goroutine 拥有独立调用栈（初始 ~2KB，动态伸缩） |
| 挂起点   | 只能在 `await` 处挂起                                        | 任意函数调用层级均可挂起/恢复，对开发者透明                            |
| 调度器归属 | `async`/`await` 是语言关键字，但事件循环是库（asyncio / trio / curio） | 编译器 + 运行时原生集成，M:N 调度器是 runtime 核心组件               |
| 编译产物  | `async def` 编译为状态机对象，每次 `await` 是状态转换                  | goroutine 由 runtime 直接管理，Go 1.14+ 引入基于信号的抢占式调度    |

---

## 二、调度与执行

| 维度   | Python                                     | Go                                            |
| ---- | ------------------------------------------ | --------------------------------------------- |
| 调度方式 | 纯协作式：必须 `await` 让出控制权，否则饿死其他协程             | 抢占 + 协作混合：函数调用点检查调度；1.14+ 信号抢占，长时间运行也会被中断     |
| 线程模型 | 默认单线程，所有协程在一个事件循环中切换                       | M:N 多线程，goroutine 自动分配到多个 OS 线程，默认使用全部 CPU 核心 |
| 并行能力 | **无真并行**：单线程并发，GIL 限制多核利用；CPU 密集需借助多进程/线程池 | **真并行**：无 GIL，多 goroutine 可同时跑在多核上            |
| 适合场景 | 高并发 I/O（网络请求、爬虫、API）                       | I/O 和 CPU 密集型通用，语言层面统一                        |

---

## 三、与线程的关系

### 协程 vs 线程

| 维度   | Python 协程   | Python 线程   | Go goroutine     | OS 线程       |
| ---- | ----------- | ----------- | ---------------- | ----------- |
| 调度   | 用户态协作式      | 内核态抢占式      | 用户态抢占+协作         | 内核态抢占式      |
| 栈开销  | 极轻量（对象+状态机） | MB 级        | KB 级（2KB 起，动态伸缩） | MB 级（1~8MB） |
| 切换成本 | 函数调用级       | 内核上下文切换（微秒） | 用户态切换（纳秒）        | 内核上下文切换（微秒） |
| 并行   | 无（GIL）      | 受限（GIL）     | 有（多核）            | 有（1:1 映射）   |
| 创建上限 | 数万级         | 数千级         | 数十万~百万级          | 数千级         |
| 通信   | 通常不共享内存     | 共享内存+锁      | 推荐 channel，也可共享  | 共享内存+锁      |

### 协程与线程的桥接

- **Python**：协程跑在主线程的事件循环中。`loop.run_in_executor()` 将阻塞操作交给线程池，`await` 取回结果，形成"协程 + 线程"混合模型。真正的并行仍需 `multiprocessing`。
- **Go**：goroutine 由 runtime 自动映射到 OS 线程池（开发者无需关心）。阻塞系统调用时 runtime 将 goroutine 从当前线程解绑，让其他 goroutine 继续执行，线程不会被浪费。

## 🎯 总结

| 维度 | Python 协程 | Go goroutine |
|------|------------|-------------|
| 实现 | 语法 + 库（asyncio） | 语言 + 运行时原生 |
| 调度 | 协作式，单线程 | 抢占+协作，多线程并行 |
| 执行 | 单线程并发，无真并行 | 多线程真并行 |
| 与线程 | 依赖线程，需手动桥接 | 替代线程，runtime 自动管理 |
| 学习成本 | 需理解事件循环、`await`、回调 | `go func()` + channel |

---

## 💡 哲学差异

- **Python 协程**：异步编程模型，解决 I/O 等待，强调"显式异步"——程序员管理控制流。
- **Go goroutine**：并发执行模型，解决并行+并发，强调"隐式并发"——程序员只管业务逻辑。

> 一句话：Python 协程让你"写异步代码"，Go goroutine 让你"写并发程序"。
